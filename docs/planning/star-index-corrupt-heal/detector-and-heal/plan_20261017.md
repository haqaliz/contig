**Goal:** the corrupt STAR log classifies `missing_index` @0.85 instead of `tool_crash`.

**Files:**

**Steps (TDD):**
1. RED — in `tests/test_detect.py`, beside the existing STAR tests
   (`:299-324`), add `test_star_corrupt_genome_index_is_missing_index`:
   `diagnose_failure([TaskEvent(process="STAR_ALIGN", status="FAILED", exit=1)],
   log_text="EXITING because of FATAL GENOME INDEX FILE error: transcriptInfo.tab is "
   "corrupt, or is incompatible with the current STAR version\nSOLUTION: re-generate "
   "genome index")` → assert `failure_class == "missing_index"`, `confidence == 0.85`,
   evidence contains the matched line. Confirm it currently returns `tool_crash`.
2. GREEN — in `diagnose_failure`, adjacent to the STAR branches (after the
   version-incompatible branch, `detect.py:295`), add an AND-guarded branch:
   ```python
   # STAR's corrupt/partial-index error: the message names an index file and says it
   # "is corrupt". Guarded on BOTH the STAR index-file phrase AND "corrupt" so it
   # cannot steal from missing_reference / the single-file branches.
   star_corrupt_lines = [
       line
       for line in _matching_lines(log_text, ("genome index file error",))
       if _has_any(line, ("corrupt",))
   ]
   if star_corrupt_lines:
       return Diagnosis(
           failure_class="missing_index",
           root_cause="STAR's genome index is corrupt or was not fully built.",
           evidence=star_corrupt_lines,
           confidence=0.85,
       )
   ```
3. Negative controls (R8) — add: (a) a bare `"genome index file error"` line with no
   `corrupt` → not `missing_index`; (b) a `corrupt` line with no STAR phrase → stays
   `tool_crash`; (c) re-assert the existing positive tests still pass.
4. Append one golden case to `detector_corpus.jsonl` (28 → 29):
   ```json
   {"case_id":"star-corrupt-index","description":"STAR genome index corrupt or partially built; FATAL GENOME INDEX FILE error","source":"synthetic","events":[{"process":"STAR_ALIGN","status":"FAILED","exit":1,"task_id":null,"name":null}],"log_text":"EXITING because of FATAL GENOME INDEX FILE error: transcriptInfo.tab is corrupt, or is incompatible with the current STAR version\nSOLUTION: re-generate genome index","expected_class":"missing_index"}
   ```

**Validation:** `uv run pytest tests/test_detect.py tests/test_corpus.py` green;

## Testing strategy

- **Unit:** detector branch + negatives (`test_detect.py`); `_is_star_signature` /
  `_parse_missing_index` routing (`test_self_heal.py`).
- **Integration (real loop):** the heal scenario through `run_heal_scenario`
  (`test_heal_scenarios.py` / `test_self_heal.py`).
- **Guard/regression:** `test_corpus.py` (100%), `test_heal_scenarios.py` (counts),
  `test_snapshot_history.py`; then the four CLI guards.
- **Manual (post-merge) gate:** a real corrupt STAR index against a real
  `--star_index` run; confirm the branch fires and the rebuild+redirect recovers.

## Environment & secrets

None. No new dependency (stdlib only). No network.

## Edge cases & error handling

- Corrupt line with a `.fai/.bai/…` token → single-file branch still wins
  (`self_heal.py:143-146`); pin with a control.
- `params["star_index"]` absent at heal time → honest `index_unresolvable` (no false
  repair); pin it.
- `genomeParameters.txt`-corruption is already caught by the existing missing branch
  (it names that file) — the new branch is specifically for a *different* corrupt
  index file naming no path.
- Wording drift → branch never fires (degrades to today's `tool_crash`), never a false
  positive.
