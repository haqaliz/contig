## Locked design decisions (from PRD review)

1. **The "strictly larger, else blind" guard lives in the pure sizer** as a new
   optional `current_gb: int | None = None` parameter on
   `peak_informed_memory_gb`. When `current_gb` is `None` the sizer returns the
   raw candidate (tier-a-consistent "no clamp in the helper" contract, mirroring
   `test_sub_current_peak_returns_raw_target_no_clamp`). The call site always
   passes it.
2. **Tiers:** `"oom_task"` (unchanged, no guard — shipped behavior), `"sibling_peak"`
   (new: candidate strictly exceeds `current_gb`), `"sibling_dominated"` (new:
   sibling evidence existed but candidate ≤ `current_gb`; caller falls to blind),
   `"unavailable"` (unchanged: no sibling evidence either).
3. **`PeakSizing` gains `source_name: str | None = None`** (defaulted, last
   field). Only the sibling tier populates it (tier a keeps `None` so existing
   NamedTuple-equality tests are untouched).
4. **Walltime branch untouched** (already global-max; roadmap prose corrected in
   Phase 4 only). **FailureCase corpus fold-in deferred** (PRD Out of Scope).
5. **`sibling_peak` detail wording:** provably `candidate ≤ 1.5 × current < 2 ×
   current = blind` when the tier fires (a surviving sibling's peak is bounded by
   the failed limit), so the detail states `vs blind x2` statically — no
   beat/tied computation needed (unlike the walltime branch, where the observed
   can be censored *above* the limit).

## Edge cases & error handling

- **Trace with `process` column absent** → fallback to `name`; all existing
  fixtures (heal scenarios, `_trace`, `TRACE_OOM/OK`) byte-identical.
- **Sibling peak tie** → first row in file order (`max` with `key`); deterministic.
- **All sibling peaks zero/dash** → `unavailable`, not `sibling_dominated`
  (distinction pinned by test).
- **Current limit unparseable/absent** → `_lead_number(…, _DEFAULT_MEMORY_GB)`
  default; never a crash; blind path preserved.
- **Sibling candidate ≤ current** → `sibling_dominated`, blind `× 2` applied —
  never a no-op retry with an unchanged limit.
- **OOM'd task's own peak present** → tier a fires, sibling logic never reached
  (siblings are only consulted when `observed` is empty) — shipped behavior
  byte-identical.
- **Ceiling clamp / never-shrink / `gave_up_at_ceiling`** — untouched;
  `apply_patch` seams unchanged.
