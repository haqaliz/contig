1. **RED.** Add tests for `_is_remote_work_dir`:
   - `"s3://bucket/work"` → `True`; `"gs://b/w"` → `True`; `"az://c/w"` → `True`
   - `"file:///abs/work"` → `False`
   - `"/local/work"` → `False`; `"relative/work"` → `False`; `""` → `False`

   - `"s3://bucket/work/"` (trailing slash) → `True`
2. **RED.** Add tests for the note builder `_remote_work_dir_note(work_dir)`:
   - returns a **single line** (`"\n" not in note`) (A3)
   - starts with `"[contig]"` (A4)
   - contains the work dir string
   - contains at least one `_SALIENT_TOKENS` entry — **import the real tuple from
     `contig.corpus` and assert against it**, never a hardcoded copy, so the test breaks
     if that vocabulary changes (A3)

```python
def _is_remote_work_dir(work_dir: str | Path) -> bool:
    """True when work_dir names a non-local URI (s3://, gs://, az://, ...).

    Keys on "://" and never a bare ":" so a Windows drive letter (C:\\work) stays
    local. file:// is deliberately local -- it names a local path with a scheme.
    """
    text = str(work_dir)
    if "://" not in text:
        return False
    return not text.startswith("file://")


def _local_work_path(work_dir: str | Path) -> Path:
    """Resolve a local work dir, accepting a file:// URI as the path it names."""
    text = str(work_dir)
    if text.startswith("file://"):
        return Path(urlparse(text).path)
    return Path(text)


def _remote_work_dir_note(work_dir: str | Path) -> str:
    """One self-labelled line explaining why task errors could not be read.

    Deliberately NOT log-shaped: the caller files this text into the failure corpus
    as evidence, and log-shaped prose would put words in Nextflow's mouth
    (the rule stated at self_heal.py:1279-1289). Deliberately carries the salient
    token "cannot" so normalize_signature (corpus.py:225-244) keeps the line and
    these cases cluster on their own instead of collapsing into the constant
    empty-log signature.
    """
    return (
        f"[contig] cannot read task errors: work dir {str(work_dir)!r} is remote; "
        "Contig reads .command.err from the local filesystem only."
    )
```

   Add `from urllib.parse import urlparse` to the imports.

**Validation:** `uv run pytest tests/test_runner.py -q` green.

**Commit:** `test(runner): pin the remote-work-dir rule and the honest note`

def read_task_errors(work_dir: str | Path, max_tasks: int = 10, tail_lines: int = 40) -> str:

## Phase 3 — Raise-safety on both halves of the log expression

**Goal:** PRD M6. Neither reader can abort diagnosis.

**Prerequisites:** Phase 2.

**Files:** `src/contig/runner.py`, `tests/test_runner.py`.

**Steps:**

1. **RED.** Tests:
   - an unreadable `.command.err` (`chmod 000`) among two tasks → the *other* task's
     text is still returned, no exception (A9). Guard with

     containing the replacement char, does not raise (A10)

   - In `read_run_log` (`runner.py:1185-1188`), add `errors="replace"` to the
     `read_text()` call, matching its sibling.

## Testing strategy

- **Unit** (`tests/test_runner.py`): the remote rule truth table, note shape, reader
  dispatch, `file://`, no-I/O-on-remote, raise-safety.
- **Integration** (`tests/test_self_heal.py`): the headline A1 test through the real
  `self_heal_run` loop with scripted executors.
- **Guard regression**: `contig eval-guard` / `contig heal-guard` must be **unmoved**.
- **Manual (post-merge, not CI):** a real `--work-dir` Nextflow run is the only way to
  observe this end to end. Record it as a manual gate, as every prior C2/C8 slice did.
- Commands: `uv run pytest -q`. No dashboard change, so no `npm` step.

## Environment & reproducibility

No env vars, no external tools, no version pins touched. Determinism: every new test is
decided by on-disk fixtures and pure string rules — no clock, no network, no real
Nextflow. No bundle field, signed payload, or `models.py` change, so **not a signature
break**.
