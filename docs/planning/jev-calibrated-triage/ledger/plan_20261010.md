## 4. Testing strategy

- Unit: report purity (zero rows, shadow rows only, skipped rows, confidence
  buckets); ledger load tolerance (missing file, malformed line, non-UTF-8);
  CLI text + `--json` shapes; exit codes (absent ledger ⇒ 0, honest note).
- Integration: write a real ledger via `append_ledger_row` in a tmp runs dir,
  then `contig triage-stats --runs-dir` over it (round-trip).
- Manual: after a real keyed run later (owner gate).
- Commands: `.venv/bin/python -m pytest tests/test_triage_stats.py -q`; full
  `.venv/bin/python -m pytest`; `uv run contig eval-guard`; `uv run contig heal-guard`.

## 5. Environment & reproducibility

- Read-only over the sidecar; deterministic given the same ledger bytes.
- No env vars consumed; no network.

## 6. Edge cases & error handling

- Ledger absent/empty ⇒ exit 0 + honest note; never a failure, never a
  fabricated "0 rows means calibrated".
- Malformed/non-UTF-8 lines ⇒ skipped + counted in the report's skipped-lines
  field (never a crash).
- Cross-tab granularity: confidence is per-decision, outcome per-check-status —
  the report labels the bucket denominators explicitly (spec's warning).
- Runs dir unreadable ⇒ honest error, exit non-zero (mirror repair_stats's
  behavior on a missing directory).
