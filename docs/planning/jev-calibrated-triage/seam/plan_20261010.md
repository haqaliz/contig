## 2. Implementation phases

### Phase 1 — Pure types, NullTriage, payload builder

- **Goal:** the seam contract with zero network: `Triage` Callable alias,
  `TriageResult`, `NullTriage`, `build_triage_payload` with the single whitelist
  declaration.
- **Prerequisites:** none.
- **Files:** create `src/contig/triage.py`, `tests/test_triage.py`.
- **Steps (TDD):**
  1. RED: `tests/test_triage.py` — `NullTriage(...)` returns `TriageResult
     (mode="null", confidence=None, items={})` and touches nothing;
     `build_triage_payload` accepts `(run_meta: dict, checks: list[dict])` and
     emits exactly the whitelisted keys, never arbitrary keys.
  2. Shape (from spec.md in-scope): `Triage = Callable[[TriageRequest], TriageResult]`;
     `TriageRequest` dataclass: `run_id`, `surface` (`Literal["qc_anomaly",
     "verify_concordance"]`), `mode` (`Literal["shadow", "active"]`), `payload:
     dict`; `TriageResult` dataclass: `mode`, `confidence: float | None` (0-1 or
     None = no triage), `items: dict[str, float]` (item id → confidence, ids are
     `{run_id}:{surface}:{check}`).
  3. Whitelist: one module constant `PAYLOAD_WHITELIST` (check-level numeric keys:
     `check`, `kind`, `status`, `value` (numeric only), `expected_range`; run-level
     numeric/metadata keys: `run_id` (opaque), `assay`, `pipeline`, `task_counts`,
     `failed_tasks`, `repair_attempts`, `verdict` (only the string rendered), file
     `sizes` + `sha256` (never paths)); `build_triage_payload` drops anything not
     whitelisted and filters non-numeric `value`s.
  4. Mutation control test (spec.M): a check dict carrying `{"path": "/reads/x.fastq",
     "bytes": b"ACGT..."}` never appears in the constructed payload — the whitelist
     drops it; the test asserts raw-read keys are absent (walk the payload for
     `fastq`/`bam`/`vcf`/`path`/`bytes` tokens).
  5. GREEN; REFACTOR.
- **Validation:** `uv run pytest tests/test_triage.py -q` green; full suite green.
- **Commit:** `feat(triage): triage seam types, NullTriage, whitelisted payload builder`

### Phase 2 — JevTriage: env gate + transport + defensive parse

- **Goal:** `default_jev_triage` behind `CONTIG_JEV_KEY`, https-only urllib POST,
  30 s timeout, size-bounded response, defensive JSON parse; absent key ⇒ Null
  behavior with **no request constructed** (asserted).
- **Prerequisites:** Phase 1.
- **Files:** extend `src/contig/triage.py`, `tests/test_triage.py`.
- **Steps (TDD):**
  1. RED: key absent ⇒ `default_jev_triage(req)` returns the Null `TriageResult`
     and the transport hook is never called (monkeypatch the module's `_urlopen` /
     a new `requests_hook` seam; assert not called). `_post_json` (the only network
     touch point, mirroring `paper_intake._urlopen` precedent) is module-level and
     patched in tests.
  2. RED: non-https `CONTIG_JEV_URL` (e.g. `http://evil.example`) refused by
     `default_jev_triage` → Null behavior + reason (`TriageResult.mode="null"`);
     `http://localhost:*` accepted only when `CONTIG_JEV_ALLOW_HTTP` is true.
  3. RED: `_post_json(url, payload, timeout=30, max_bytes=...)` → returns raw text;
     a 500/connection error/timeout ⇒ Null behavior, never raises. Response size
     bound (`_MAX_TRIAGE_RESPONSE_BYTES`, default 64 KiB, house `_UPPER_SNAKE`
     pattern) enforced with honest `"oversized"` reason.
  4. RED: `parse_triage_response(text)` — `{"items": [{"id", "confidence"}]}`;
     ids without a matching payload key are dropped (a response item always
     addresses a real check); malformed JSON, non-dict, missing `items`,
     non-list, confidence outside [0,1], unknown ids ⇒ Null behavior / drop, never
     raise (defensive parser precedent: `detect._extract_json_object`,
     `claim_extraction._extract_json_list`).
  5. GREEN; REFACTOR. Confirm `CONTIG_JEV_KEY` is never included in any payload or
     logged (a test asserts the key name does not appear in `build_triage_payload`
     output).
- **Validation:** `uv run pytest tests/test_triage.py -q`; full suite green;
  `uv run pytest tests/test_triage_live.py -q` shows 1 skipped.
- **Commit:** `feat(triage): JevTriage env-gated https transport with defensive parse`

## 5. Environment & reproducibility

- `CONTIG_JEV_KEY` — BYOK bearer key; absent ⇒ Null (documented, required to be
  absent in CI).
- `CONTIG_JEV_URL` — https endpoint; absent/empty ⇒ Null behavior (documented; no
  hard-coded vendor URL because the vendor contract is unverified — recorded, not
  papered over).
- `CONTIG_JEV_ALLOW_HTTP` — manual-gate opt-out; documented; off by default.
- Determinism: all tests inject `_post_json`; no network, no real clock; repeat is
  byte-deterministic.

## 6. Edge cases & error handling

- DNS/conn error, HTTP error, timeout (30 s) ⇒ Null behavior; never raise; never
  change caller behavior.
- Oversized response ⇒ Null with `"oversized"` reason; malformed JSON ⇒ Null;
  non-list `items` ⇒ Null; unknown item ids dropped; out-of-[0,1] confidence
  dropped.
- Absent/empty key: no request constructed (asserted), no file, no env read of the
  key value beyond `os.environ.get` (never logged; payload test asserts the key
  name never appears in a payload).
- URI edge: scheme parsing must not raise on garbage input (`http://`, `https://`,
  missing scheme ⇒ Null with reason); `urllib.parse` used, never regex-only.
