### Phase 2 — Wrap sites: qc_anomaly ledger capture + verify-time skip surface

- **Goal:** the two PRD-R5 sites. qc_anomaly: consult the seam AFTER the trigger
  fires, always fire the trigger itself, append a ledger row. Verify-time: the
  only active-mode skip surface, gated by the R4 predicate; skipped ⇒ honest
  UNVERIFIED note + ledger row.
- **Prerequisites:** Phase 1.
- **Files:** `src/contig/triage.py` (+`is_skippable_check`, +`append_ledger_row`),
  `src/contig/self_heal.py`, `src/contig/cli.py`, `tests/test_triage_wiring.py`.
- **Steps (TDD):**
  1. RED: `is_skippable_check(kind: str, bands: Mapping | None) -> bool` —
     True iff `kind == "concordance"` or (`bands` present and no `fail_*` key;
     band keys are `warn_below`/`warn_above`/`fail_below`/`fail_above`, see
     `rule_pack.py:545-564`). Enumeration test walks the shipped `_RULE_PACKS`
     and asserts the skippable set by name — MUST include `ts_tv`, `het_hom`,
     `variant_count`, `somatic_variant_count` as NOT skippable, and e.g.
     `spearman_concordance`/`somatic_site_overlap`/`consequence_concordance` as
     skippable; a future FAIL band joining a skippable rule is a deliberate act
     (test reddens).
  2. RED: `append_ledger_row(runs_dir, row: dict)` writes one line to
     `<runs_dir>/triage-ledger.jsonl` (append-only, `errors="replace"`, never
     raises; unwritable path degrades silently). Row keys: `run_id`, `attempt`,
     `surface`, `mode`, `confidence`, `reason`, `checks` (ids), `actual` (status
     summary string). Ids from `TriageRequest`/`TriageResult` item ids.
  3. RED — qc_anomaly site (`self_heal.py:1250-1319`): after the trigger block
     writes its `RepairStep` (untouched), build a `TriageRequest` (surface
     `qc_anomaly`, payload from the failed-check list via `build_triage_payload`),
     call the seam (consumer of the injected kwarg), and append a ledger row with
     the actual = the QC-FAIL verdict fact. Trigger output is byte-identical with
     any seam (Null, shadow, active) — asserted by a test.
  4. RED — verify-time dispatch (`cli.py:2188-2232`): after the dispatch resolves
     the evaluator + its check id, build the request (surface
     `verify_concordance`, payload from the run record's QC results + run
     metadata), call the seam; in **active** mode with confidence < threshold AND
     `is_skippable_check` true: skip the evaluator, append an honest
     UNVERIFIED result (`kind="concordance"`, message naming the threshold + skip
     reason), ledger row `actual="skipped"`, and exit code unchanged. In shadow/
     null: run the evaluator, ledger row with the actual result status. A skipped
     concordance check never changes the stored record or exit code (concordance
     is at-most-WARN / UNVERIFIED is neutral in the reduction).
  5. RED — verdict-identity: `contig verify` with triage off vs shadow ⇒
     byte-identical output on the checks that ran; active with a fake seam
     returning confidence ≥ threshold ⇒ identical; active with confidence <
     threshold on a concordance check ⇒ the UNVERIFIED result appears and
     nothing else changes. `--fail-on-verdict` semantics unchanged.
  6. GREEN; REFACTOR.
- **Validation:** new tests green; full unit suite green; guards unmoved.
- **Commit:** `feat(triage): qc_anomaly ledger capture and verify-time skip surface`

## 4. Testing strategy

- Unit: flag refusal matrix; `is_skippable_check` enumeration (rule-pack walk);
  `append_ledger_row` write/tolerance/absent-sidecar; qc_anomaly identity with
  Null vs shadow vs active seam; verify identity tests incl. the skipped-check
  UNVERIFIED shape; heal-guard byte-identical scenarios.
- Integration: `contig verify` end-to-end against the repo's synthetic demo run
  with a fake seam injected via the CLI test harness (deterministic, no network).
- Manual: owner smoke later via the live gate (seam aspect).
- Commands: `uv run python -m pytest tests/test_triage_wiring.py -q`, then full
  `uv run python -m pytest`; `uv run contig eval-guard`; `uv run contig heal-guard`.

## 5. Environment & reproducibility

- Env read-only here: key presence decides null/shadow/active; tests control env
  with monkeypatch (never a real key in CI).
- Determinism: seams injected where the loop runs; no network; no real clock.
- Signed record untouched: the skipped-check UNVERIFIED result is a verify-time
  presentation only (concordance results are per-invocation, not persisted into
  the stored record). Re-verify with triage off reproduces the original checks.

## 6. Edge cases & error handling

- Threshold present without active → refusal (never silently ignored).
- Active without key → refusal naming `CONTIG_JEV_KEY` (before any run/verify
  work).
- Seam failure mid-call → Null behavior (seam aspect guarantees), the ledger row
  still records `reason="triaging failed degradedly"` with `confidence=None`.
- Ledger unwritable → silent, never a run/verify failure.
- Skip surface in active mode: only current-invocation concordance checks;
  structural/FAIL-capable rules never reach it (predicate + enumeration test).
- qc_anomaly trigger always fires: seam consultation happens after, never gates
  the Diagnosis/pending-corpus capture.
