## Phase 1 — The trigger (the substance)

**Goal:** a green run whose QC reduces to FAIL produces one diagnosed `qc_anomaly` step.

**Prerequisites:** Phase 0.

**Files:** `src/contig/self_heal.py`, `tests/test_self_heal.py` (or a new
`tests/test_qc_anomaly_trigger.py` — prefer a new file, the existing one is large).

**Steps:**

1. **RED first.** Write the failing tests for **A1–A5, A9, A10, A12, A17** before touching
   production code. Reuse the existing `_trace(status, exit)` helper pattern and injected-executor
   style already in `tests/test_self_heal.py`. A17 builds a record shaped like the real
   `runs/variant-bad` bundle: one `COMPLETED`/exit-0 event, `ts_tv_ratio:S1` FAIL,
   `het_hom_ratio` + `mean_coverage` PASS.
2. Add a module-level constant next to the other outcome strings:
   `QC_VERDICT_FLAGGED_OUTCOME = "qc_verdict_flagged"`. **One constant, referenced by both the
   production path and the heal scenario assertion** — `RepairStep.outcome` is an unenforced
   `str`, so a typo would otherwise silently diverge (RISK-4).
3. Insert the trigger **between `self_heal.py:984` and `:985`**, i.e. between the
   `record = run_pipeline(...)` assignment and the `return _finalize(...)`. Guard on all three R1
   conditions, in this order (cheapest first, and condition 1 first because it is the one that
   prevents misattribution):

   ```
   if RunSummary.from_events(record.events).succeeded
      and record.qc_results
      and overall_verdict(record.qc_results) == "fail":
   ```

   Do **not** key on `record.verdict == "fail"` — that is `"fail"` for a failed **event** before
   QC is consulted (`models.py:373-385`), which would misattribute a crash as a QC anomaly (A2).
4. Build the `Diagnosis` inline (no `detect.py` change, no `diagnose_failure` call):
   `failure_class="qc_anomaly"`, `confidence` per Phase 0's finding (default `1.0`),
   `root_cause` naming the count of FAILed non-informational checks, `evidence` = the failing
   check names with their statuses, taken from `record.qc_results`.
5. Record it via the existing `_record_attempt(run_dir, repair_history, RepairStep(...))` with
   `patch=None` and `outcome=QC_VERDICT_FLAGGED_OUTCOME`. `detail` carries the count, the check
   names, the assay, and the explicit reason no repair was attempted (a `-resume` retry is
   100% cache-hit and re-derives an identical verdict) — this is R12's field instrument, and it
   must use **one consistent greppable message stem**.
6. Fall through to the **existing** `return _finalize(...)` — do not add a second call site
   (A9). The trigger must not `continue` (A10): there is no retry.

**Validation:** `uv run pytest tests/test_qc_anomaly_trigger.py -v`, then the full
`uv run pytest`. A2 and A5 are the tests a wrong implementation passes everything else while
failing — treat them as the load-bearing pair (the `no_progress` slice's
`test_stall_message_with_incidental_exit_137_is_still_no_progress` played this role).

**Commit:** `feat(self-heal): diagnose a QC-FAIL verdict on a green run as qc_anomaly`

   e.g. `qc_artifact: Literal["empty_vcf_gz"] | None = None`. Default `None` keeps all 8 existing

   like a VCF to a human reading it; both produce the identical FAIL.
   *Mechanism, for the implementer:* `parse_vcf` opens a `.gz` name with stdlib `gzip`

   `variant_metrics` returns `variant_count=0`, and `VARIANT_RULE_PACK`'s

   - `scenario_id: "qc-anomaly-verdict-flagged"`, `expected_class: "qc_anomaly"`

     `RunSummary.succeeded` is true and R1's condition 1 holds

     activates the VCF plausibility path)
   - `qc_artifact: "empty_vcf_gz"`, `expected_outcome: "qc_verdict_flagged"`
   - **`expected_recovered: true`** — see **D8** below. The `description` field must state why.
5. Refreeze deliberately: `uv run contig heal-guard --update-baseline`. Update the hardcoded
   literals in `tests/test_heal_scenarios.py` (`scenario_count` 8 → 9, `corpus_sha`, recovery

### D8 — the `recovery_rate` artifact: disclose, do not redefine

`run_heal_scenario` computes `recovered = RunSummary.from_events(record.events).succeeded`
(`heal.py:130`) and diverges the scenario if it ≠ `expected_recovered` (`heal.py:145-148`), which
would drop the **guarded** `outcome_match_rate`. Our run is green from attempt 1, so `recovered`
is `True` and `expected_recovered` **must** be `true` — even though **nothing was recovered**.
Consequence: `recovery_rate` moves 5/8 = 0.625 → 6/9 ≈ 0.667 as a pure artifact.

**Decision: accept and disclose.** Every shipped scenario starts FAILED, so event-success and
"healed" have always coincided; ours is the first to break that conflation. Redefining
`recovered` (e.g. treating `qc_verdict_flagged` as not-recovered) would retroactively change the
meaning of all six recorded `heal_history` points to fix a cosmetic artifact in a metric that is
documented **informational-only and never guarded**. The CHANGELOG must state plainly that the
`recovery_rate` rise is an artifact of a green-by-construction scenario and **not** an
improvement. Redefinition is recorded as deferred.

**Validation:** `uv run contig heal-guard` → `covered_classes` 7, `outcome_match_rate` 1.0 (A15);
`uv run pytest`.

## Testing strategy

- **Unit (Phase 1–2):** the trigger's three conditions, the negative cases, the contract
  invariants. **A2 and A5 are the discriminating tests** — an implementation keying on
  `record.verdict` alone, or ignoring the `informational` filter, passes everything else and
  fails exactly these two.
- **Integration (Phase 3):** the frozen scenario replayed through the real `self_heal_run` with
  the real `_discover_qc` — no QC mocking anywhere in this slice.
- **Regression (A17):** a record shaped like the real `runs/variant-bad` bundle.
- **Guards:** `uv run contig eval-guard` (must stay 0.923) and `uv run contig heal-guard`
  (7 classes, outcome-match 1.0), both already wired into `.github/workflows/ci.yml:20-27`.
- **Manual gate (pre-merge, not CI):** confirm on a real green-but-QC-FAIL run that the report
  and dashboard render the new step sensibly, and that the exit code is unchanged. No real
  nf-core run happens in CI.

## Environment & reproducibility

No env vars, no external tools, no new dependency (stdlib `gzip` only, already imported in the
codebase). No change to `LaunchManifest`, the reproduce bundle, or signing — `repair_history`
is already signed and round-tripped; Phase 0 step 3 verifies no existing signature breaks.
Determinism: the heal scenario writes a fixed-byte artifact and asserts a fixed outcome.

## Edge cases & error handling

| Case | Expected |
|---|---|
| Empty `qc_results` | silent skip (`unverified`, never `fail`) — A3 |
| FAILED event + returncode 0 | **not** `qc_anomaly` — A2 |
| FAIL from an `informational` check only | no trigger — A5 |
| `warn` / `pass` / `unverified` | no trigger — A4 |
| Trigger on a retried attempt that finally succeeds green with FAIL QC | fires once, on that final attempt only — A10 |
| Pending-corpus write fails (unwritable path) | must not break the run; the exception path's existing behaviour governs — verify it is equally tolerant |

## Phase 0 findings (2026-07-28) — Checkpoint 1 TRIPPED

**Python renderers are all honest; the dashboard misreports in two ways.** Verified empirically
by building a green-run record with one `qc_verdict_flagged` step and calling the real renderers.

**Text/HTML/progress output (real, captured):**

```
VERDICT: FAIL
Tasks: 1 (0 failed)
QC checks:
  - ts_tv_ratio:S1: FAIL (value 0.5)
Repair history:
  - attempt 1: qc_anomaly → none patch → qc_verdict_flagged
```

No "gave up", no "run failed", no failure banner, no inflated attempt count. The FAIL verdict is
pre-existing for any green-but-QC-FAIL run, not introduced here. `_finalize`'s notification kind
is decided by `RunSummary.succeeded` (`self_heal.py:1319-1322`), **not** by history — so A7 holds
by construction. Only cosmetic nits (`Repair history:` over a step that repaired nothing).

**🔴 FINDING 1 — `Repaired` badge on a green run.** `dashboard/lib/derive.ts:27` defines
`wasRepaired` as `repair_history.length > 0`; `runs-table.tsx:196-203` renders a **`Repaired`**
badge from it. Our step would claim a repair that never happened. **Also pre-existing:** today's
`gave_up` steps carry `patch=null` and already trigger the badge falsely. **Decision (founder,
at Checkpoint 1): fix the definition** — the badge means *a patch was applied*. Fixes ours and
the pre-existing case. See Phase 3.5.

**🔴 FINDING 2 — unknown outcome falls through to give-up styling.**
`dashboard/components/run/repair-timeline.tsx:62-67` falls back to `OUTCOME_META.gave_up.className`
for any unmapped outcome; the map (`:38-60`) has only `patched_and_retried`,
`stopped_for_confirmation`, `gave_up`. Verified: `OUTCOME_META["qc_verdict_flagged"] === undefined`.
So the new literal renders with **give-up styling** and a raw snake_case label — never printing
"Gave up", but dressed as one, defeating D4's whole reason for a distinct literal. Likewise
`FAILURE_LABELS` (`:20-27`) lacks `qc_anomaly`, yielding `"Qc Anomaly"`.
**This is the only switch-on-outcome-literal in the codebase — no Python code branches on one.**

**FINDING 3 — transient live-view window (disclose, do not engineer around).** `_record_attempt`
writes `repair_progress.jsonl` before `_finalize` writes the bundle, so while finalize runs
(checksum hashing over the results tree) a dashboard poll can show `Self-heal attempts: 1` and a
`Self-healing in progress` card. Self-clearing. Reordering the trigger after `_finalize` would
break A9's single-call-site invariant, so this is **disclosed in the CHANGELOG, not fixed**.

**O3 — `self_heal.py:971` is the only production caller of `run_pipeline`.** `run`/`rerun`/`resume`
all funnel through `_dispatch_run` → `self_heal_run`; `contig reproduce` uses a separate path with
its own `ReproduceRecord.repair_history`. **Scoped-by-design, nothing lost.** Keep the
`RunSummary.succeeded` guard anyway: it documents intent, it is what A2 tests, and it is insurance
against a future `run_pipeline` that returns instead of raising.

**O4 — signatures provably safe.** `repair_history` is already a signed field with a `[]` default
(`models.py:336`), so `b'"repair_history"'` is **already in the canonical bytes of every existing
bundle**. A pre-existing bundle's canonical bytes, `signed_sha256`, and detached signature are
bit-identical before and after this slice, verified across a real `write_bundle` → `load_bundle`
round-trip. **No signature-break disclosure needed** (unlike three prior C8 slices). One
implementer constraint: adding a *value* to the existing optional `RepairStep.detail` is fine;
**renaming or re-defaulting any `RepairStep`/`Diagnosis` field is not** — that would alter the
canonical bytes of records that already carry steps.

**Critique gap 3 — use `1.0`; D6 stands.** No consumer treats the range as open above 0.95.
`Field(ge=0.0, le=1.0)` makes it legal by construction; `_is_ambiguous` uses a strict `<` on the
*lower* bound (and is unreachable here — no gated patch); `diagnose_failure_strict` never reads
`confidence`; the dashboard formatter renders `1.0` as `(100% confidence)`; no corpus/eval code
reads it at all. Two supporting facts: the codebase's **own LLM clamp ceiling is `1.0`**
(`detect.py:606-609`), and `tests/test_corpus.py:241` **already constructs `confidence=1.0`**.
`0.99` would be a fabricated hedge on a deterministic fact.

**Corrections to this plan, from the dig:**

1. **Phase 1 step 3:** `overall_verdict` is **not** imported in `self_heal.py` — the import at
   `:35` is `Diagnosis, ExecutionTarget, Patch, QCResult, RepairStep, RunRecord, RunSummary`.
   Extend it.
2. **Phase 4 step 1:** take the **code** as ground truth for the uncovered-class list —
   `cli.py:2681-2687` currently lists `permission_denied` (this plan omitted it) and does **not**
   list `reference_not_bgzf` (this plan included it).
3. **Citation drift:** `_is_ambiguous`'s `def` is at `self_heal.py:260`, not `:262`. All other
   citations in this plan verified exact.
4. **Free empirical support for A3:** a green run through the real `self_heal_run` in a bare
   tmpdir yields `qc_results == []` → `verdict "unverified"`, so the `record.qc_results` guard
   short-circuits. **All 8 shipped heal scenarios (`assay: rnaseq`, no QC artifact) are
   structurally unable to trip the trigger** — cite this in the Phase 1 commit.
5. **No existing test asserts the absence of a repair block on a green run**, so Phase 1 adds the
   first such coverage rather than modifying an assertion.

dependencies, a config, a changed `npm test`, and a `ci.yml` edit — project-level decisions
outside a two-file phase, and against this plan's stated no-new-dependency constraint. Both
behaviours in scope are DOM-observable, so strict RED → GREEN is achievable as-is.

**Assertion discipline** (to keep the tests from rotting): assert the **user-visible text** as
the primary contract (`Repaired` absent; "QC verdict flagged" and "QC anomaly" present), and for
give-up distinctness assert the **negative** — that the element does *not* carry `gave_up`'s
class — rather than pinning an amber/Tailwind class string, which would test the stylesheet
instead of the behaviour. `e2e/fixtures/testpass2` (one `gave_up` step, `patch=null`, currently
showing `Repaired`) is the RED target for the pre-existing-misstatement fix.

functions like `derive.ts` can only be exercised through a browser. Worth its own slice;
