## Environment & reproducibility

- No env vars, no new tools, no network, no real nf-core/samtools/GATK in CI — all fixtures
  on-disk synthetic; the heal scenario replays the real `self_heal_run` with the scripted
  executor seam.
- Determinism: fixture logs are literal strings; guard numbers are committed; baselines
  refrozen only via `--update-baseline` (documented deliberate acts).

## Edge cases & error handling

- A CRAM line containing an absence phrase → must still classify the new class (control ii);
  if the AND-guard fights the `missing_index` absence needles, narrow the CRAM needle
  further (e.g. require a decode-phrase, not a path token).
- The bare token "cram" must never fire (non-match control 4).
- `diagnose_failure_strict` needs no change (the new class is not on the weak-evidence
  demotion list; verify by running the strict tests).
- The refreeze sequence: eval-guard FIRST, heal-guard SECOND — if heal-guard's refreeze
  changes `contig_version` in the baseline, the order is still fine (baselines are
  independent files).
