## 1. The contract to build against

### Module API

```python
# --- taxonomy -------------------------------------------------------------
APPLIED_OUTCOMES: frozenset[str]        # 7
DECLINED_OUTCOMES: frozenset[str]       # 3
GAVE_UP_OUTCOMES: frozenset[str]        # 7
FLAGGED_OUTCOMES: frozenset[str]        # 1  qc_verdict_flagged
ACKNOWLEDGED_OUTCOMES: frozenset[str]   # 1  advisory_acknowledged_and_retried
OUTCOME_FAMILY: dict[str, str]          # literal -> "applied"|"declined"|"gave_up"|"flagged"|"acknowledged"

ATTENDED_OUTCOMES: frozenset[str]           # rejected_by_user, approval_timed_out,
                                            # invalid_choice_rejected,
                                            # advisory_acknowledged_and_retried
ATTENDANCE_UNKNOWN_OUTCOMES: frozenset[str] # approved_and_retried, chose_and_retried

_THIN_THRESHOLD = 3                     # mirrors corpus.py:279

# --- classifiers (pure) ---------------------------------------------------
def classify_applied(outcome: str, raw_step: dict) -> str:
    """'applied' | 'not_applied' | 'legacy_derived' | 'unknown'."""

def classify_attendance(outcome: str) -> str:
    """'attended' | 'unattended' | 'attendance_unknown' | 'unknown'."""

def derived_applied(outcome: str) -> bool | None:
    """For a legacy step: True iff APPLIED-family. None for an unmapped literal."""

# --- aggregation (pure) ---------------------------------------------------
@dataclass(frozen=True)
class LoadedRun:
    run_id: str
    record: RunRecord
    raw_steps: list[dict]   # the raw repair_history dicts, straight from JSON

def repair_stats_report(runs: list[LoadedRun]) -> dict: ...

# --- loading (I/O) --------------------------------------------------------
def collect_runs(runs_dir: str | Path) -> list[LoadedRun]: ...
```

The pure/I-O split mirrors `coverage_report(cases)` + `load_corpus(path)`
(`corpus.py:291`, `:40`): the CLI aspect calls `collect_runs` then
`repair_stats_report`, and every aggregation test runs with **no file I/O at all**.

### Report dict shape

```python
{
  "runs": {
    "total": int,
    "analyzable": int,              # len(record.events) > 0
    "not_analyzable": int,          # zero-event; excluded from the rate entirely
    "attendance_unknown": int,      # any step in ATTENDANCE_UNKNOWN_OUTCOMES
    "rate_denominator": int,        # analyzable - attendance_unknown
    "unattended_completed": int,    # in denominator AND succeeded AND no attended step
    "unattended_completion_rate": float | None,   # None when denominator == 0
  },
  "steps": {
    "total": int,
    "by_family": {family: count},                 # per STEP
    "by_failure_class": {class: count},           # per STEP, from step.diagnosis
    "by_applied": {"applied": n, "not_applied": n, "legacy_derived": n, "unknown": n},
    "by_attendance": {"attended": n, "unattended": n,
                      "attendance_unknown": n, "unknown": n},
    "legacy_derived_applied": {"applied": n, "not_applied": n},
  },
  "thin": [failure classes with fewer than _THIN_THRESHOLD steps],   # sorted
  "unmapped_outcomes": {literal: count},          # sorted; e.g. stopped_for_confirmation
}
```

Every dict is built with `sorted()` keys for determinism, matching `cli.py:3732`'s
`sorted(report["per_class"].items())` discipline.

**Rate rules (from PRD R3/R4 + Addendum 2):**
- `not_analyzable` runs are in **neither** numerator nor denominator.
- `attendance_unknown` runs are in **neither** numerator nor denominator.
- `succeeded` is `RunSummary.from_events(record.events).succeeded` (`models.py:156-158`),
  never `RunRecord.verdict` (which conflates completion with QC quality).
- A run is attended if **any** step is attended — not last-step-wins.
- `unattended_completion_rate` is `None`, never `0.0`, when the denominator is 0.

## 2. Implementation phases

Each phase is RED → GREEN → REFACTOR, one agent, suite green at the end.

### Phase 1 — Taxonomy constants + the two structural pins

- **Goal:** the 19-literal map exists and cannot silently rot.
- **Prerequisites:** none.
- **Files:** create `src/contig/repair_stats.py` (constants only),
  `tests/test_repair_stats.py`.
- **Steps:**
  1. RED — write AC-9 (union of the five families == the documented 19-literal set;
     families pairwise disjoint) and AC-10 (`derived_applied(x) is True` ⟺
     `x in APPLIED_OUTCOMES`, over every mapped literal). Both fail: no module.
  2. GREEN — write the five frozensets, `OUTCOME_FAMILY` derived from them (never
     hand-written twice), `ATTENDED_OUTCOMES`, `ATTENDANCE_UNKNOWN_OUTCOMES`,
     `derived_applied`.
  3. Module docstring must state **why** a hand-maintained derived map is acceptable here
     when `CHANGELOG.md:869-876` rejected one for the model field: the pre-v0.49.0 record
     set is **frozen**, so the map cannot rot. Without this a reviewer will reasonably
     object.
  4. Cite `dashboard/components/run/repair-timeline.tsx:86-192` in a comment as the
     mirror source.
- **Validation:** `uv run pytest tests/test_repair_stats.py -q` green (2 tests).
- **Commit:** `feat(repair-stats): the 19-literal outcome taxonomy, pinned to the shipped families`

### Phase 2 — The two three-state classifiers

- **Goal:** answer the two under-determined questions in three states.
- **Prerequisites:** Phase 1.
- **Files:** modify both.
- **Steps:**
  1. RED — AC-1 (key omitted + `patched_and_retried` → `legacy_derived`, derived applied
     true), AC-2 (key present `false` → `not_applied`), AC-3 (key present `true` →
     `applied`), AC-4 (`stopped_for_confirmation` → `unknown` on both axes, never
     `gave_up`, never derived), AC-6 (`advisory_acknowledged_and_retried` → `attended`
     **and** not applied).
  2. GREEN — `classify_applied(outcome, raw_step)`: `"patch_applied" not in raw_step` →
     `legacy_derived` (or `unknown` if the literal is unmapped); else the bool verbatim.
     `classify_attendance(outcome)`: unmapped → `unknown`; in `ATTENDANCE_UNKNOWN_OUTCOMES`
     → `attendance_unknown`; in `ATTENDED_OUTCOMES` → `attended`; else `unattended`.
  3. Comment at `classify_applied` explaining the raw-dict parameter: `models.py:322`
     declares `patch_applied: bool = False`, so the **validated model cannot** distinguish
     absent from false — the raw dict is the only source for key presence. Without this
     comment the parameter reads as redundant.
- **Validation:** `uv run pytest tests/test_repair_stats.py -q` green (7 tests).
- **Commit:** `feat(repair-stats): three-state applied and attendance classifiers`

### Phase 3 — Pure aggregation

- **Goal:** `repair_stats_report` over in-memory `LoadedRun`s. No file I/O.
- **Prerequisites:** Phase 2.
- **Files:** modify both.
- **Steps:**
  1. RED — AC-5 (a succeeded run whose only step is `approved_and_retried` is in neither
     side of the rate), AC-7 (zero-event run → `not_analyzable`, excluded), AC-8 (a 2-step
     run yields **two** family rows and **one** run in the rate), AC-11 (empty input → a
     report with `unattended_completion_rate: None`, no ZeroDivisionError, no `0%`).
  2. GREEN — `LoadedRun` dataclass; `repair_stats_report` per the shape above; a test
     helper building `LoadedRun`s from `RunRecord` + hand-written raw step dicts.
  3. **Fixture discipline (RISK, spec):** the helper must let a test **omit** the
     `patch_applied` key entirely, distinct from setting it `False`. If the helper always
     emits the key, AC-1 passes vacuously. Assert the distinction in the helper's own test
     or via AC-1/AC-2 being genuinely different fixtures.
- **Validation:** `uv run pytest tests/test_repair_stats.py -q` green (11 tests);
  `uv run pytest -q` green overall.
- **Commit:** `feat(repair-stats): per-step and per-run aggregation with a guarded rate`

### Phase 4 — The loader

- **Goal:** `collect_runs(runs_dir)` reads each bundle twice, deliberately.
- **Prerequisites:** Phase 3.
- **Files:** modify both.
- **Steps:**
  1. RED — a `tmp_path` test writing two bundles via `write_bundle` (the `_write_run`
     idiom, `tests/test_cli.py:132-138`), one of them post-edited on disk to **remove**
     the `patch_applied` key, asserting `collect_runs` returns both and that the edited
     one classifies `legacy_derived`. Plus: missing dir → `[]`.
  2. GREEN — reuse `workspace.list_run_ids` and `workspace.load_run`; separately
     `json.loads(bundle_dir_for(...)/"run_record.json")` for `raw_steps`. Do **not**
     re-roll directory walking.
  3. Skip-and-record a record that fails to load rather than crashing the whole report
     (`load_corpus` raises, but that is a single curated file; a runs dir is user data and
     one bad bundle must not blind the rest). Verified: all 15 real records load cleanly

- **Validation:** `uv run pytest tests/test_repair_stats.py -q`; then `uv run pytest -q`.
- **Commit:** `feat(repair-stats): load run bundles for stats, model plus raw key presence`

## 3. File-by-file build order

1. `src/contig/repair_stats.py` — the whole aspect. Exports the constants,

## 4. Testing strategy

- **Unit (Phases 1-3):** entirely in-memory. No `tmp_path`, no bundle writing — this is
  the payoff of splitting `collect_runs` out.
- **Integration (Phase 4):** `tmp_path` + `write_bundle` + a post-write JSON edit to
  produce a genuine legacy record.
- **Manual (post-merge, not CI):** run against the real corpus —
  `uv run contig repair-stats --runs-dir /Users/aliz/dev/at/contig/runs` — once
  `cli-surface` lands, and compare to the PRD's prediction (15 runs, 1 not-analyzable,
  7 steps all `legacy_derived`, APPLIED ×2 / GAVE_UP ×4 / unknown ×1, classes
  `tool_crash` ×3 / `oom` ×2 / `missing_index` ×1 / `unknown` ×1, 0 read from the field).
  **A discrepancy is the finding, not a test failure.**
- **Commands:** `uv run pytest tests/test_repair_stats.py -q`, then `uv run pytest -q`
  (baseline: 2796 passed / 1 skipped at v0.56.0 — must not regress).

## 5. Environment & reproducibility

No env vars, no external tools, no network, no real Nextflow. Deterministic by
construction: every dict `sorted()` by key, no timestamps, no wall-clock, no randomness.
Nothing enters a bundle or the signed payload — this aspect is read-only over existing
artifacts, which is what lets it satisfy the "no new instrumentation" wording of the
revisit trigger it serves (`CAPABILITY_ROADMAP.md:617`).

## 6. Edge cases & error handling

| Case | Behaviour |
|---|---|
| Missing / empty runs dir | `collect_runs` → `[]`; report with rate `None`. Never `0%`. |
| Bundle fails to validate | Skipped and counted, not raised. (Defensive — none exist today.) |
| Step with an unmapped literal | `unknown` on both axes; counted in `unmapped_outcomes`; never derived, never folded into `gave_up`. |
| Zero-event run | `not_analyzable`; out of both sides of the rate. |
| Run with `approved_and_retried` | `attendance_unknown`; out of both sides of the rate. |
| Run with empty `repair_history` | A clean first-attempt success (verified: `self_heal.py:1199`, single call site `cli.py:792`, no resume-of-history path). Counts as unattended completion if it succeeded. |
| `rate_denominator == 0` | Rate is `None`. Never `0.0` — the two mean different things. |
| `step.failure_class` | Never read. The class lives on `step.diagnosis.failure_class`. |

## 7. Agent execution notes

- **Checkpoint after Phase 2.** The two classifiers are the whole intellectual content of
  the slice; everything after is bookkeeping. Review them before aggregation is built on
  top.
- **Likeliest place to need iteration:** the Phase-3 fixture helper. Getting "key absent"
  vs "key false" genuinely different in fixtures is fiddly and is exactly where a vacuous
  pass hides.
- **Ask before proceeding if:** any real emitted literal is found that is not in the
  19-literal set (the map would be wrong, not just incomplete), or if `_THIN_THRESHOLD`
  reads badly against **steps** rather than the corpus **cases** it was designed for — the
  threshold may want a different value here, and that is a judgement call worth surfacing
  rather than silently picking.
- **Do not** touch `models.py`, `report.py`, or `cli.py` in this aspect. `cli.py` belongs
  to `cli-surface`; `report.py`'s binary renderer is an accepted divergence (PRD
  R-Risk-2), not an oversight to fix in passing.
