## 1. The command

Mirror `coverage` (`cli.py:3706-3736`) exactly — same decorator style, same
`typer.echo`-only rendering, same `_json.dumps(report)` for `--json`, same
`sorted()`-everything discipline. No Rich tables anywhere in this family.

```python
@app.command(name="repair-stats")
def repair_stats(
    runs_dir: str = typer.Option("runs", "--runs-dir", help="Directory holding run bundles."),
    json_out: bool = typer.Option(False, "--json", help="Emit the report as JSON (for the dashboard)."),
) -> None:
```

Body: `runs = collect_runs(runs_dir)`; if `--json`, `typer.echo(_json.dumps(report))` and
return; else render the text block below. No `FileNotFoundError` guard is needed —
`collect_runs` returns `[]` for a missing dir by design (unlike `load_corpus`, which
raises; do **not** copy `coverage`'s try/except here, it would be dead code).

### Text rendering — the actual product of this aspect

The numbers already exist; this is where they either read as rigour or as breakage. The
real-corpus output (PRD Addendum 3) is the worked example. Target shape:

```
Repair stats: 15 run(s), 7 repair step(s).
  unattended completion: 9/14 analyzable run(s) (64.3%)
    1 run(s) not analyzable (no task events) -- excluded from both sides
  by outcome family (per step):
    applied: 2
    gave_up: 4
  by failure class (per step):
    missing_index: 1  THIN
    oom: 2  THIN
    tool_crash: 3
    unknown: 1  THIN
  patch enacted (per step): read 0, legacy-derived 6, unknown 1
    of the 6 legacy-derived: applied 2, not applied 4
  unmapped outcome(s): stopped_for_confirmation=1
  note: over real runs -- not `heal-guard`'s recovery_rate, which scores synthetic scenarios.
```

Required properties, each with a test:

1. **Every total labelled `run(s)` or `step(s)`.** No unlabelled number.
2. **The rate names its own denominator inline** (`9/14 analyzable run(s)`), never a bare
   percentage.
3. **The `not_analyzable` exclusion is stated with its reason** ("no task events"), and
   only when it is non-zero.
4. **The `attendance_unknown` exclusion is stated when non-zero**, naming why the record
   cannot say (a human or `--auto-approve`; the flag is not persisted). Zero on today's
   corpus, so this line is exercised by fixture only.
5. **Legacy disclosure is unconditional when any step is legacy-derived** — "read 0" is the
   sharpest fact in the whole report and must not be inferable only by subtraction.
6. **`THIN` suffix** exactly as `cli.py:3733` does it. (The worry that it would fire on
   every class is settled: `tool_crash` at 3 escapes — PRD Addendum 3.)
7. **The `heal-guard` disambiguation note is always printed** (PRD R8 makes it a
   requirement, not a nicety).
8. **`rate is None` renders as "not computable"**, never `0.0%`. The two mean different
   things.
9. **No runs at all** → `No runs found in {runs_dir}.` and return, mirroring
   `list_runs` (`cli.py:2721`). Never `0%`.

## 3. Testing strategy

Fixtures use `CliRunner()` + `tmp_path` + `contig.bundle.write_bundle`, following the
`_write_run` idiom at `tests/test_cli.py:132-138`. This command needs real
`run_record.json` files, so raw JSONL is not an option.

**The load-bearing fixture:** for the legacy case the test must write the bundle and then
**post-edit the JSON on disk to delete the `patch_applied` key** — `model_dump_json`
always emits it, so without that edit there is no genuine legacy record and the
disclosure test passes vacuously. `stats-core`'s Phase-4 tests already do this; reuse the
approach.

**Determinism:** two invocations over the same fixture must produce byte-identical output.

## 4. Edge cases

| Case | Behaviour |
|---|---|
| Missing/empty runs dir | "No runs found in {dir}." exit 0 |
| All runs not analyzable | rate "not computable", denominator 0 stated |
| No repair steps at all | family/class blocks omitted, not printed empty |
| No legacy steps | legacy line omitted (nothing to disclose) |
| No unmapped outcomes | line omitted |
| `attendance_unknown` > 0 | its own exclusion line |

## 5. Agent execution notes

- The text block **is** the deliverable. A correct dict rendered unreadably fails this
  aspect even with every test green — read the rendered output against PRD Addendum 3's
  worked example before declaring done.
- Do not add a `try/except FileNotFoundError` copied from `coverage`; `collect_runs`
  cannot raise it.
- Do not print the rate without its denominator anywhere, including in `--json` prose.
- Ask before proceeding if the honest text runs past ~15 lines: verbosity that gets
  skimmed defeats the disclosures, and trimming is a judgement call worth surfacing.
