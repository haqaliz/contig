## 2. API amendment (from the spec — implement exactly this)

```python
@dataclass(frozen=True)
class MatchOutcome:
    claim_id: str
    value: float
    scale: Literal["raw", "pct"] | None
    locator: Locator | TableLocator | None
    site_count: int
    reason: Literal["bound", "ambiguous", "refused_low_information", "no_candidates"]
    semantic_match: str | None = None   # NEW additive field, default None

def match_claims(candidates, claims, *, metrics: Mapping[str, Sequence[str]] | None = None) -> list[MatchOutcome]: ...
def sidecar_text(outcomes, claims) -> str: ...
```

- `metrics` is keyword-only; a non-dict raises `TypeError` at call time (pinned).
- `semantic_match`: the matched header/leaf key(s) that narrowed the pool —
  exactly one distinct match → that key; several distinct matches → sorted
  comma-joined; `None` when the value-only path ran (metrics absent, unknown
  claim id, or zero header matches).
- The five pre-existing `MatchOutcome` fields keep their order and meaning;
  positional construction with the original five fields still works.
- `semantic_match` is set whenever the semantic filter ran for the claim,
  INCLUDING a semantic no-candidates miss; it is `None` only for the
  value-only fallback.

## 3. Implementation phases (each an agent-owned TDD unit)

### Phase A: Semantic filter core + API amendment

- **Goal**: `match_claims` narrows by metric-word/header matching; fallback is
  byte-identical to the shipped behavior.
- **Files**: `locator_match.py`, `test_locator_match.py`.
- **Steps (strict RED → GREEN)**:
  1. RED — update the `MatchOutcome` field-pin test (the Phase-1
     get_type_hints pin) to the seven-field shape with `semantic_match` last.
  2. RED — private helpers:
     - `_norm_header(s)` — lowercase, keep alnum only;
     - `_header_matches(header, words)` — equality or containment either way
       after normalization; pins: "Recovery %" matches "recovery";
       "log2FoldChange" does NOT match "fold change" (no token-boundary
       rule is defined — pinned as a documented default); "n_recovered"
       matches "recovered" (word ⊂ header); "recovery_rate" matches
       "recovery" (header ⊂ word);
     - `_leaf_key(path)` — last string token of a JSON dotted+`[n]` path
       (an `[n]` int tail means no key → no semantic match for that
       candidate). Pins: `m.auc` → "auc"; `rows[0].v` → "v"; `xs[0]` → None.
  3. RED — `match_claims` semantic behavior:
     - claim with words ["recovery"] against a fixture repo whose `recovery`
       column holds the value once → `bound`, `semantic_match` == "recovery";
       same claim WITHOUT metrics → the value-only outcome (ambiguous on a
       dense-table fixture) — both sides pinned;
     - several distinct matching headers → `semantic_match` is the sorted
       comma-joined keys;
     - semantic no-candidates: value absent from its semantic column →
       `no_candidates` WITH `semantic_match` set;
     - fallback: unknown claim id → value-only (semantic_match None);
       words matching no header → value-only;
       `metrics=None` → byte-identical outcomes to no-arg calls (compare
       `match_claims(c, claims)` vs `match_claims(c, claims, metrics={})`
       and vs `match_claims(c, claims, metrics={"other": ["x"]})` for
       equality of outcomes);
     - `metrics="not-a-dict"` → TypeError (call-time, pinned);
     - JSON leaf-key semantics: candidate in `results.json` at `m.auc`
       matches words ["auc"] → bound with `semantic_match` == "auc";
       a list-index leaf (`xs[0]`) has no key → value-only path;
     - never-raises holds: garbage metrics values (None words, empty lists,
       non-str words) degrade to fallback, not exceptions.
  4. GREEN — implement: subsetting before value matching, semantic_match
     bookkeeping, M9 unchanged and still applied BEFORE matching, exactly-one
     / dual-scale / site-granularity rules untouched inside the pool.
  5. REFACTOR — keep helpers private; no public surface beyond the pinned API.

## 6. Edge cases & error handling

- Multiple distinct matching headers per claim → sorted comma-joined
  `semantic_match`; the pool contains all matching columns' cells — exactly-one
  still decides.
- List-index JSON leaves have no key → value-only fallback for that candidate
  (documented; a future key-inference is out of scope).
- Metric words that are empty / non-str / missing id → fallback, never raise.
- Semantic narrowing can only shrink a pool; the universal assertion guards it.
- M9 runs before matching, unchanged (a refused claim is refused whether or
  not metrics are given).
- Freshness/R6: unchanged (inference proposes sites; verdicts under the
  closure guard; R6 disclosure already in the sidecar).
