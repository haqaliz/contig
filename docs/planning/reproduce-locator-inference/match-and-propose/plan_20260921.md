## 3. Implementation phases (each an agent-owned TDD unit)

### Phase 1: Module skeleton + precision/equality core

- **Goal**: `locator_match.py` exists with `MatchOutcome` and the private
  equality helpers; all equality semantics pinned before any matching logic.
- **Files**: `tests/verification/test_locator_match.py` (new),
  `src/contig/verification/locator_match.py` (new).
- **Steps (strict RED → GREEN)**:
  1. RED — tests for the private helpers (import them via module prefix for
     testing, sweep precedent):
     - `_printed_precision(value: float) -> int`:
       - `0.9134` → 4; `0.91` → 2; `12.5` → 1; `87.0` → 0 (int-valued float);
       - scientific-notation repr (`1e-05`, `1.5e-07`) → sentinel meaning
         "exact compare" (documented default: no rounding, exact equality);
       - clamp: never more than 12.
     - `_value_matches(candidate_value, claim_value, scale, precision) -> bool`:
       - raw scale: integer-valued claim (`float.is_integer()`) → **exact
         equality, no rounding** (avoids the ±0.5 window at 0dp: `875.6` must
         NOT match `876`); float-valued claim → `round(candidate_value,
         precision) == round(claim_value, precision)` (exact equality after
         rounding — `0.9134` vs claim `0.91` → match at 2dp);
       - pct scale: same rules with `claim_value / 100` and `precision + 2`
         (dividing by 100 shifts two decimal places: claim `87` → compare
         `0.87` at 2dp; claim `0.91` → `0.0091` at 4dp);
       - int/float nuance: `7 == 7.0` is True in Python — round-trip a test
         where a JSON int leaf (`value=7`) matches a float claim `7.0`, and the
         reverse;
       - NaN/inf candidate values never match (sweep already rejects
         non-finite, but guard defensively); non-finite claim value → the
         caller (Phase 2) records `no_candidates`, never raises.
  2. GREEN — implement the two helpers + `MatchOutcome` + module docstring
     stating the honesty contract (evidence-gated, never inference from the
     paper; G1 self-graded; R6 accepted-and-disclosed).
  3. REFACTOR — keep helpers private; no public surface beyond the pinned API.
- **Validation**: `.venv/bin/python -m pytest tests/verification/test_locator_match.py -q` green.
- **Commit**: `feat(locator_match): printed-precision equality core (aspect 2/3)`

### Phase 2: `match_claims` — site grouping, exactly-one, dual-scale, M9

- **Goal**: the full matching rule, pure and never-raises.
- **Files**: extend `test_locator_match.py`, extend `locator_match.py`.
- **Steps (RED → GREEN)**:
  1. RED — `match_claims` tests:
     - one JSON candidate matching at raw scale → `bound`, `Locator(source,
       path)` fields carried verbatim from the `Candidate` (`source` = repo-
       relative POSIX path; `path` = the sweep's dotted+`[n]` expression —
       never synthesized);
     - one table candidate (header mode: str `column`, data-row int `row`,
       `header=True`) → bound complete `TableLocator`; headerless mode
       (int column, all-rows int row, `header=False`) → bound complete;
       `delimiter` never set;
     - same value at two different sites (two JSON leaves; one JSON + one
       table cell; two table cells in different rows) → `ambiguous`,
       `site_count=2`, `locator=None`; the per-scale site count recorded;
     - same value at the **same** site twice (two candidates with identical
       source+coordinate — e.g. duplicate table rows) → counts as ONE site →
       bound;
     - pct scale: claim `87` (int) against repo `0.87` → bound with
       `scale="pct"`; claim `0.91` against repo `0.0091` → bound `pct`;
       claim matching raw AND pct at different sites → `ambiguous`;
     - M9 refusals → `refused_low_information`, `locator=None`: deny-list
       values `0`, `1`, `0.5`, `0.05`, `100` (and float forms `0.0`, `1.0`,
       `0.5`, `0.05`, `100.0`) and any integer with ≤ 2 significant digits
       (`87`, `870`, `1234` passes); `site_count=0`;
     - no matches at either scale → `no_candidates`, count = 0;
     - non-finite claim value (e.g. `float("inf")`, loadable by `load_claims`)
       → `no_candidates`, never raises;
     - empty `claims` → `[]`; empty `candidates` → one `no_candidates` outcome
       per claim; claims order preserved;
     - garbage input never raises: `Candidate` with `kind="json"` but
       `path=None` (defensive skip), `kind="table"` with `column=None` or
       `row=None` (defensive skip), unknown `kind` (skip).
  2. GREEN — implement: `_site_key(candidate)` = `(source, path)` for json /
     `(source, column, row)` for table; group matches per scale; apply M9
     before matching (refusal short-circuits); M9 as a module constant
     `_LOW_INFORMATION_DENY = frozenset({0.0, 1.0, 0.5, 0.05, 100.0})` +
     `_INT_SIG_DIGIT_CAP = 2` — conservative uncalibrated engineering
     defaults, documented as such; deterministic order (candidates already
     sorted by source from `sweep_repo`; do not re-sort).
  3. REFACTOR — keep helpers private.
- **Validation**: full `test_locator_match.py` green; suite still green
  (`.venv/bin/python -m pytest -q`, expect 3083 + new).
- **Commit**: `feat(locator_match): evidence-gated candidate matching (aspect 2/3)`

## 6. Edge cases & error handling

- `Candidate.value` may be `int` (JSON leaves) or `float` (table cells) —
  comparisons float-safe (`7 == 7.0`), pinned.
- Integer-valued claims: exact equality (no rounding window); M9 refuses
  integers with ≤ 2 significant digits.
- Scientific-notation reprs: exact compare, documented default, pinned.
- Non-finite claim value: `no_candidates`, never raises.
- Defensive skips: malformed `Candidate` (missing coordinate fields, unknown
  `kind`) — skip, never raise, never crash other claims.
- Empty claims → `[]`; empty candidates → `no_candidates` per claim.
- Freshness: inference proposes binding sites only; the verdict is decided
  under the unchanged `_require_fresh` closure at reproduce time — pinned by
  the stale-artifact test. R6 (stale-coordinate/fresh-path) is disclosed in
  the sidecar, not solved.
