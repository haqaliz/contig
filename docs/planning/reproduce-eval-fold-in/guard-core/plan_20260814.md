## Phase B — Scenario driver (real machinery, scripted seams)

**Goal:** `run_reproduce_scenario(scenario, *, repo_dir, run_started_at, installer)`
replays one scenario through the **real** `run_reproduction` — real
`load_claims`, real `classify`, real locators, real freshness guard — with only
the executor/installer seams scripted.

**Prerequisites:** Phase A.

**Files:**
- modify `src/contig/reproduce_guard.py`
- create `tests/test_reproduce_guard_driver.py`

**Steps (TDD):**
1. Failing tests first:
   - **Fresh-artifact exact match:** flat claim, executor step 1 writes
     `results.json` with `os.utime` mtime **exactly** `run_started_at`; observed
     status REPRODUCED; record.exit_code 0; no repair.
   - **Stale-artifact → UNVERIFIED:** same fixture but `artifact_mtimes` sets
     mtime `< run_started_at` (e.g. `run_started_at - 1`); the located claim is
     UNVERIFIED (freshness guard, never a false pass).
   - **stdout-mode pattern claim** (`PatternLocator(source=None)`) binds the
     captured output — no artifact write needed.
   - **Env-resurrection heal:** executor steps = [(1, "No module named 'x'"),
     (0, "")], installer step rc 0; `allow_install=True`; the retried run's
     results.json drives REPRODUCED; observed repair ==
     `installed_and_retried`; `ReproduceRecord.repair_history` has one step
     with `failure_class="missing_dependency"`.
   - **Install-fail give-up:** installer rc 1 → observed repair
     `install_failed`, claims UNVERIFIED.
   - **Non-zero exit, no install:** executor returns (5, "") → all claims
     UNVERIFIED.
   - **Claims validated through real `load_claims`:** a scenario whose inline
     claims are schema-invalid (e.g. duplicate id) raises `ClaimsError` — the
     driver must not construct Claims by hand.
   - **Unexpected extra executor call raises** (loud scenario bug, not silent).
   - Determinism: identical results with `run_started_at=1_000_000.0`
     (the repo-wide convention).
2. Implement: the driver writes `scenario.claims` to `<repo_dir>/claims.json`,
   loads via **real** `load_claims` (propagate `ClaimsError` — scenario bug),
   builds a scripted executor closure that pops `ExecStep`s in call order —
   each call returns `(exit_code, output)` and writes `write_results` (as the
   scenario's `results_path` content) and `write_artifacts` (repo-relative
   paths) with `os.utime(path, (mtime, mtime))` where mtime =
   `artifact_mtimes.get(path, run_started_at)` — and a scripted installer
   popping `installer_steps` (or rc 0 default). Calls `run_reproduction` with
   the injected `run_started_at`, `allow_install`, the installer, and the
   standard deterministic identity (`claims_sha256="a"*64`,
   `created_at="2026-07-18T00:00:00Z"`, `reproduce_id="rp_1"`). Returns
   `(record, claims)`.
3. Add a small pure helper `claim_family(claim) -> str` (`flat`/`json`/`table`/
   `pattern`/`notebook` via isinstance on the locator) — used in Phase C.

## Phase C — Scorer, snapshot, comparator, baseline/history I/O

**Goal:** `evaluate_reproduce(scenarios, *, run_started_at)` → report;
`snapshot_from_reproduce_report`; `save/load_reproduce_baseline`;
`compare_reproduce_to_baseline` — mirroring `verify_corpus.py`.

**Prerequisites:** Phase B.

**Files:**
- modify `src/contig/reproduce_guard.py`
- create `tests/test_reproduce_guard_scorer.py`

**Steps (TDD):**
1. Failing tests first:
   - **Match semantics (exact):** a scenario matches only when every expected
     claim status equals the observed status AND expected repair equals
     observed repair AND expected exit code equals record.exit_code. A
     scenario with one wrong status → not matched. UNVERIFIED never equals
     REPRODUCED.
   - **known_miss:** a scenario with `known_miss=true` whose expected status is
     deliberately wrong still scores as a mismatch (metadata only).
   - **Anti-tautology mutation control:** take a frozen scenario, flip one
     expected status → the scenario's match flips (proves re-derivation, never
     stored-status comparison). Also flip a `classify`-adjacent input (the
     observed value in the scenario) → match flips.
   - **Per-family rates:** claims across families accumulate per-family
     matched/total; `covered_families` lists every family present.
   - **Snapshot:** `outcome_match_rate` = matched/total scenarios (the guarded
     number); `recovery_rate` = healed scenarios / total (informational);
     `corpus_sha` = sha256 over the scenarios file bytes (`sha256_file`,
     `models.py:17`); `contig_version` from the version module used by the
     siblings.
   - **Baseline compare:** regression when `rate < baseline.rate - tolerance`;
     improvement when `> + tolerance`; `sha_mismatch` / `version_mismatch`
     informational; pass otherwise — match `compare_verify_to_baseline`
     semantics (verify_corpus.py:387-435).
   - **History:** `append_jsonl` / `load_jsonl` round-trip a `ReproduceSnapshot`
     through `src/contig/snapshot_history.py`.
2. Implement per the verify_corpus.py shape. Run each scenario through the
   Phase B driver (one `run_started_at` per scenario, injected from a single
   call-site value so the whole evaluation is deterministic).

**Validation:** `uv run pytest tests/test_reproduce_guard_scorer.py` green; full suite green.
**Commit:** `feat(guard): reproduce scorer, snapshot, baseline compare (C6 fold-in)`

## Edge cases & error handling

- Stale artifacts → UNVERIFIED by the real freshness guard (never a false
  pass) — the stale scenario is a feature, not a bug.
- Schema-invalid inline claims → `ClaimsError` propagates (scenario bug is
  loud; CI fails).
- Executor called more times than `executor_steps` → raise (loud).
- Malformed JSONL lines in the scenarios file → skip with the
  `load_verify_cases` pattern (`verify_corpus.py:314-330`), never crash.
- `run_started_at=None` never reaches `run_reproduction` — the driver always
  injects a value.
- Non-finite observed values → UNVERIFIED via real `classify` (never DIVERGED).
- Baseline JSON placeholder `{}` is replaced only in Phase D — do not commit a
  guard run against the placeholder.
