## Testing strategy

- Unit (written first, per phase): capture writes per family; low-`n_shared`
  semantics; one-annotator absence; messages byte-identical; family-key
  enumeration; round-trip through `verification_case_from_run`.
- Guard (never edited, must stay green): `contig verify-guard` /
  `eval-guard` / `heal-guard` — composition must not move them.
- No integration/manual stage: no real pipeline runs in CI, per repo discipline.

## Environment & reproducibility

- `uv sync` (already done); no new dependency; stdlib-only.
- Determinism: all fixtures are on-disk strings / tiny VCFs under `tmp_path`; no
  clock, no network, no subprocess.
- Signature contract: only new values in the existing additive
  `verification_inputs` field on new runs — no model change, no validator, no
  signature break.

## Edge cases & error handling

- Low `n_shared` (union/shared < 10): capture raw values; re-derivation →
  `unverified` — matches the QCResult, never a false pass.
- Only-annotator / ambiguous layout: no `concordance_consequence` key (honest
  absence), `annotation_plausibility` may still capture.
- Missing caller (no Strelka): no `concordance_somatic_overlap` key.
- Non-numeric `pon_applied`: excluded by construction.
- `n_shared` int → `float()` cast to honor the `dict[str, float]` contract.
