# Plan: `crate-projection` (rocrate-reference-identity), 2026-09-25

Sources: `../prd.md` (M1–M7, S1–S2) and `./spec.md` (acceptance criteria AC1–AC13).
Branch: `feat/rocrate-reference-identity/aliz`. Baseline: `tests/test_provenance.py` has 12
tests, all passing.

## 1. Overview

A pure projection change in `src/contig/provenance.py`. `to_rocrate(record)` gains:
- a list `@context` with a term map (all crates)
- reference, known-sites and annotation contextual entities (only when the record has them)

Nothing else in `src/` changes. Every phase touches the same two files, so **phases run
sequentially**: one implementer agent per phase, each in strict TDD, with the integrator
reviewing between phases. No work in parallel on the same file.

## 2. Phases

### Phase 1: Context term map + graph-unmoved pin (AC1, AC2, AC12)
- **RED** (in `tests/test_provenance.py`):
  - `test_context_maps_sha256_and_localpath`: asserts the exact list from AC1.
  - `test_graph_unmoved_without_reference_or_annotation`: builds the expected graph
    **literally in the test** (the descriptor, root with today's keys and no `mentions`,
    pipeline, sorted inputs, outputs) for `_record()`, and asserts `crate["@graph"] == expected`.
    This literal is the frozen "today" snapshot. Write it against the current code first and
    confirm it passes (a characterization test) before changing the context.
- **GREEN:** replace `_RO_CRATE_CONTEXT` usage with a module constant
  `_CONTEXT = ["https://w3id.org/ro/crate/1.1/context", {"sha256": "http://schema.org/sha256",
  "localPath": "https://w3id.org/ro/terms#localPath"}]`. Keep `_RO_CRATE_CONTEXT` as the URL
  string inside it. Return a **fresh copy** per call (`copy.deepcopy` or construct inline) so a
  caller mutating the result can't corrupt the constant.
- **Verify:** `uv run pytest tests/test_provenance.py tests/test_cli.py -k "rocrate or export or
  provenance" -q -p no:cacheprovider` shows all green.
- **Commit:** `feat(provenance): map sha256 and localPath in the RO-Crate context`

### Phase 2: Reference entities (AC3–AC7)
- **Test helper:** add a local `_ref(**kw) -> ReferenceIdentity` factory in the test file. Do not
  touch shared fixtures (`tests/conftest.py`).
- **RED:**
  - iGenomes: `#reference` + `#reference-genome-key` (EDAM `data_2340`), and no fasta/gtf nodes.
  - Explicit with both hashes: `localPath`, `encodingFormat` (`format_1929`/`format_2306`),
    `sha256`, and `hasPart` order fasta then gtf.
  - Explicit with `gtf_sha256=None`: there is no `sha256` key. With `gtf=None`, there is no GTF node.
  - `annotation_version`: null gives no `version` anywhere. A constructed `"GENCODE 44"` gives
    `version` on `#reference-gtf` only.
  - Harmonized:
    - `add_chr` gives a GTF `description` containing "harmonized" and "add_chr", plus the
      `#reference-harmonization` PropertyValue in `additionalProperty`.
    - A None direction gives a node with no `value`.
    - `harmonized=False` gives neither.
  - Root `mentions == [{"@id": "#reference"}]`, and the key comes **after** `contigVersion` in
    insertion order (assert `list(root)[-1] == "mentions"` when the versions are set).
- **GREEN:** add private builders `_reference_entities(ref) -> list[dict]` (returns
  `#reference` first, then its parts in the M6 order). Add a small `_drop_none(d)` helper so no
  key ever carries None. The `name` wording:
  - iGenomes: `f"iGenomes {key} reference (downloaded by the pipeline)"`
  - Explicit: `"Explicit reference"`
  - GTF harmonized description: `f"Contig-harmonized copy of the user's annotation (contig
    names rewritten: {direction}); not the original file"`. If direction is None, drop the
    parenthetical's direction clause.
- **Commit:** `feat(provenance): project reference identity into the RO-Crate`

### Phase 3: Known sites (AC8)
- **RED:** explicit relative path goes verbatim into `localPath`; iGenomes s3 goes to
  `contentUrl`; a `{`-pattern gives a `description` containing the verbatim path and no
  `contentUrl`/`localPath`; a duplicate role gives `#known-sites-dbsnp`, `#known-sites-dbsnp-1`;
  a null path gives only `@id`/`@type`/`alternateName`/`encodingFormat`; every known-site id
  appears in `#reference.hasPart` after fasta/gtf.
- **GREEN:** `_known_site_entities(sites) -> list[dict]`, with the role counter in a dict.
  `name` is `PurePosixPath(path).name` for local paths; for s3, take the substring after the
  last `/`. Description for a pattern: `f"Path pattern as recorded: {path}. Expands to more than
  one file; not itself a single downloadable file."`
- **Commit:** `feat(provenance): known-sites entities in the RO-Crate`

## 4. Testing strategy
- Unit tests only (a pure function). The CLI export tests (`tests/test_cli.py:4273-4301`)
  are the integration check and must pass unchanged.
- **Final gate:** the full `uv run pytest -q -p no:cacheprovider` run from **this worktree**.
  Confirm `which python` resolves to the worktree `.venv` (see the worktree venv memory).
  Read the real pass/fail counts from pytest's summary line, not from condensed tool output.

## 5. Environment & reproducibility
- There are no env vars. The stdlib only (`copy`, `pathlib`). No new dependency; the validator
  lives in a throwaway venv and never goes into `pyproject.toml`.
- Determinism: insertion-ordered dicts, record-ordered lists, no sets, no clock, no filesystem.

## 6. Edge cases
Covered above: a None record field, a relative path, the s3 brace pattern, a duplicate role, a
None direction, annotations without a reference, a reference without annotations, and the
empty `known_sites` list vs None (both give no known-site nodes).
