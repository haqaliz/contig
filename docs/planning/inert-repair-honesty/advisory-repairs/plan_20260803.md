## ⚠️ The design decision this plan turns on — read before Phase 1

`patch_applied` is sourced **solely** from `_apply_patch_and_maybe_build`'s `continue_`
(`self_heal.py:1164-1165`, `:1208`, `:1264-1268`). That was v0.49.0's whole point: correct by
construction, not by review.

But this feature needs **`patch_applied=False` AND a retry** on an approved advisory — and
today those are the same boolean. `cont=False` would correctly mark nothing-enacted but would
also skip the retry the human just approved; `cont=True` would retry but re-assert enactment.

**Resolution: an advisory never enters the applier at all.**

- Handle advisories on their own branch in `self_heal_run`, **before** the auto-approve and
  gate logic, so `_apply_patch_and_maybe_build` is never called and there is no `cont` to
  mis-source. Its 5-tuple is unchanged.
- `apply_patch` gains a defensive advisory branch that **raises** (never silently no-ops), so
  an advisory reaching the applier is a loud bug, not a quiet re-enactment.
- Structural guarantee is preserved by a different mechanism than v0.49.0's, so it must be
  pinned by its own test (Phase 1 RED #4): **no code path can produce
  `patch_applied=True` for a `kind="advisory"` patch.**

Rejected alternative: widening the tuple to 6 (`cont`, `applied`). It decouples cleanly but
touches all 11 `_record_attempt` sites and every build/recompress return, for four classes
that never fire. Revisit only if a second advisory-like kind appears.

## Phase 1 — The `advisory` patch kind (PRD R1, R3)

**Goal:** the type exists, four classes emit it, and it can never be recorded as enacted.

**Files:** `src/contig/models.py`, `src/contig/repair.py`, `src/contig/self_heal.py`,
`tests/test_repair.py`, `tests/test_self_heal.py`

### RED first — four failing tests

1. `Patch(kind="advisory", …)` validates (fails today: Literal has 6 members).
2. For each of `disk_full`, `permission_denied`, `conda_solve_failed`,
   `platform_unsupported`: `propose_patches` returns exactly one patch with
   `kind == "advisory"`, `risk == "needs_confirmation"`, and **no** machine-applicable
   operation key (assert the four inert keys are absent).
3. `apply_patch(target, advisory_patch, params)` **raises** (today it silently merges).
4. **The structural pin:** through the real loop, for every advisory class and every gate
   decision (approve / reject / timeout / auto-approve), no recorded `RepairStep` has both
   `patch.kind == "advisory"` and `patch_applied is True`.

### GREEN

- `models.py:300` — add `"advisory"` to the `kind` Literal. **Nothing else on `Patch` or
  `RepairStep` changes** — a new field would be a fifth signature break (PRD T3).
- `repair.py` — the four branches become `kind="advisory"`, rationales **kept verbatim** (they
  were always advice), inert operations removed.
- `self_heal.py` `apply_patch` — advisory branch raising a clear error before the `env` merge.

### R-Open-1 — decide here, and record the choice in the commit message

`operation` is a required `dict[str, object]` (`models.py:301`). Use **`{}`**. An empty dict is
unambiguously "no machine operation", needs no new vocabulary, and serializes without
surprising any consumer. Do **not** invent a descriptor key — anything with a name will read
as an operation to the next person, which is the exact failure being fixed.

**Validation:** `uv run pytest tests/test_repair.py tests/test_self_heal.py -q`
**Commit:** `feat(repair): four inert repairs become advisories, never claimed as enacted`

## Phase 2 — The advisory branch in the loop (PRD R4, R-Open-0)

**Goal:** an advisory pauses, records an observational outcome, and never claims enactment;
`--auto-approve` skips it.

**Files:** `src/contig/self_heal.py`, `tests/test_self_heal.py`

### RED first

1. Interactive approve → outcome `advisory_acknowledged_and_retried`, `patch_applied False`,
   and the loop **does** retry (attempt 2 runs).
2. Reject → `rejected_by_user`; timeout → `approval_timed_out`. Both `patch_applied False`.
   (These should already hold; pin them so the new branch can't regress them.)
3. `--auto-approve` + advisory → **no retry**, an honest give-up, guidance recorded, and the
   run finalizes. Assert the executor was called exactly **once**.
4. `pending_approval.json` for an advisory carries `rationale` + diagnosis/evidence and **no
   `operation` key** (PRD R5).

### GREEN

- New branch in `self_heal_run` ahead of the `auto_approve` block (`self_heal.py:1146`):
  - `auto_approve` and `gated.kind == "advisory"` → record the give-up, `_finalize`, return.
    Chosen resolution (a), approved 2026-08-03: an advisory is not applicable, so there is
    nothing to auto-apply.
  - Interactive: pause exactly as today; on approve, record
    `advisory_acknowledged_and_retried` with `patch_applied=False` and `attempt += 1; continue`
    **without** calling `_apply_patch_and_maybe_build`.
- `_write_pending_approval` — omit `operation` for advisories.

### Naming, and why

`advisory_acknowledged_and_retried` is **observational**: Contig saw an acknowledgement and a
retry. It deliberately does **not** say the human fixed anything — Contig cannot observe that
(PRD R-Risk-3). Do not rename it to anything asserting a repair happened.

**Validation:** `uv run pytest tests/test_self_heal.py -q`
**Commit:** `feat(self-heal): an advisory pauses for guidance and never records enactment`

## Phase 3 — `container_unavailable` genuinely waits (PRD R6)

**Goal:** `wait_seconds` becomes load-bearing, through an injected clock, never slept in CI.

**Files:** `src/contig/runner.py` (or wherever the seam aliases live — they are declared
together at `runner.py:593-615`), `src/contig/self_heal.py`, `src/contig/heal.py`,
`tests/test_self_heal.py`, `tests/test_heal_scenarios.py`

### RED first

1. A `container_unavailable` heal with an injected recording sleeper: the sleeper is called
   once with `15` before the retry, and the retry then happens.
2. A patch with no `wait_seconds` (e.g. `container_pull_failed`) sleeps **zero** times —
   pinning that this did not become a blanket backoff.
3. Real time never passes: assert the injected sleeper is used and `time.sleep` is not.

### GREEN

- Declare `Sleeper = Callable[[float], None]` alongside the existing seams
  (`runner.py:593-615`, the stated rationale there is exactly this: "tests inject a fake so no
  real tool runs"). **Direct precedent: the stall watchdog already takes
  `sleeper: Callable[[float], None] = time.sleep` (`runner.py:673`)** — mirror it.
- Thread `sleeper: Sleeper = time.sleep` through `self_heal_run` **and** `heal.py`'s evaluator
  (`:105-116`, wired at `:174`). **Both, or no heal scenario can cover it** and the feature
  lands outside the guard.
- In the safe-patch retry path, read `patch.operation.get("wait_seconds")` and call the
  sleeper before `attempt += 1`. Guard the type (only a positive number sleeps).
- `repair.py` — `container_unavailable` keeps `kind="retry"`, `risk="safe"`, and its
  `wait_seconds: 15`. **Its diagnosis stays distinct from `container_pull_failed`** — the two
  detector branches have disjoint needles and separate fixtures (`detect.py:136-167`,
  `tests/test_detect.py:43-55`). Do not merge them.

**Validation:** `uv run pytest tests/test_self_heal.py -q` — and confirm total suite runtime
did not grow by ~15s (proof nothing really slept).
**Commit:** `feat(self-heal): container_unavailable actually waits before retrying`

## Edge cases & error handling

- Advisory + budget exhausted → existing `gave_up` at `self_heal.py:1129-1142`, unchanged.
- Advisory + reject/timeout → unchanged literals; pin them so the new branch can't regress them.
- `wait_seconds` absent, zero, negative, or non-numeric → no sleep, no crash.
- An advisory reaching `apply_patch` → raises loudly (never a silent re-enactment).
- Multiple attempts of the same advisory class → pauses each attempt until the budget runs out.
  Acceptable and unchanged; note it rather than adding a new suppression rule.
- Snakemake → the advisory change is inert there in the same way every `set_param` repair
  already is (`snakemake.py:26-46` ignores params entirely). State it; do not fix it.
