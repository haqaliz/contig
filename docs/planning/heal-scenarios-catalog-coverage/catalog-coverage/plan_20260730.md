## Phase 1 — The `fasta_artifact` seam (PRD R4)

- **Goal:** `reference_not_bgzf` can reach the real `_recompress_reference`.
- **Prerequisites:** Phase 0.
- **Files:** `src/contig/models.py`, `src/contig/heal.py`, `tests/test_heal_scenarios.py`.

### RED first

1. `test_heal_scenario_fasta_artifact_defaults_to_none` — a `HealScenario` built without the
   field has `fasta_artifact is None` (back-compat, PRD R3).
2. `test_run_heal_scenario_reference_not_bgzf_recompresses_and_retries` — a scenario with
   `fasta_artifact="plain_gzip"`, `auto_approve=True`, attempts `[FAILED/1/bgzf-log,
   COMPLETED/0/"done"]` yields `diagnosed_class == "reference_not_bgzf"`,
   `actual_outcome == "recompressed_reference_and_retried"`, `patch_applied is True`,
   `matched is True`.

### GREEN

3. `models.py` — add to `HealScenario`, immediately after `qc_artifact` so JSONL field order
   stays stable:
   ```python
   fasta_artifact: Literal["plain_gzip"] | None = None
   ```
   Carry a comment in the `qc_artifact` house style (`models.py:563-569`): a **named fixture
   directive**, not an injected result — the driver writes a real plain-gzip FASTA and points
   `params["fasta"]` at it, because synthesizing the recompress result would stop measuring
   `_recompress_reference`.
4. `heal.py` — add `_write_fasta_artifact(tmp_dir: Path) -> Path`: create
   `tmp_dir / "fixtures"`, write `ref.fa.gz` with `gzip.open(path, "wt")` and a couple of
   FASTA records. **Plain `gzip.open` is exactly right** — it emits a plain-gzip header with
   no `BC` FEXTRA subfield, which is what `_gzip_kind` (`self_heal.py:722-751`) must classify
   as `"plain_gzip"`.
5. `heal.py` — in `run_heal_scenario`, when `scenario.fasta_artifact` is set, call the writer
   and pass `params={"fasta": str(path)}` to `self_heal_run` (currently no `params` argument
   is passed at all, so `current_params` is `{}` — `self_heal.py:977`). When unset, pass
   nothing, so the nine existing scenarios take a byte-identical path.

### Watch out — four give-up branches precede success

`_recompress_reference` (`self_heal.py:754-835`) returns `reference_recompress_unresolvable`
when there is no `fasta` in params, when the fasta is already in `built_paths`, or when
`_gzip_kind` is not `"plain_gzip"`; and `reference_recompress_failed` on `OSError`/
`EOFError`/`BadGzipFile`. If the RED test goes green with the *wrong* outcome string, the
fixture is at fault — do not adjust the expectation to match. That is exactly PRD R11's
"wrong → stop" case.

- **Validation:** `uv run pytest tests/test_heal_scenarios.py -q`; then `uv run contig
  heal-guard` still reports 9 scenarios at 100% (the seam is inert until a JSONL line uses
  it).
- **Commit:** `feat(heal-guard): add the plain-gzip FASTA fixture seam for reference_not_bgzf`

## Phase 2 — The four primary scenarios (PRD R1)

- **Goal:** each covered class replays its declared outcome through the real loop.
- **Prerequisites:** Phase 1.
- **Files:** `tests/test_heal_scenarios.py`, then `src/contig/data/heal_scenarios.jsonl`.

**Fan-out:** the four classes are independent. Dispatch one agent per class to write its test
and verify its in-code scenario. Each agent returns **(a) its test function, (b) the exact
one-line JSON record**. Agents must **not** edit `heal_scenarios.jsonl` — the integrator
appends all lines centrally, because it is one file and the append order fixes `corpus_sha`.

### Per class: RED → verify → hand back the line

| # | `scenario_id` | class | shape | expected |
|---|---|---|---|---|
| 1 | `missing-reference-approved-heal` | `missing_reference` | `auto_approve: true`; `[FAILED/1/log, COMPLETED/0/"done"]` | `approved_and_retried`, `patch_applied true`, `recovered true` |
| 2 | `reference-not-bgzf-recompress-heal` | `reference_not_bgzf` | `auto_approve: true`, `fasta_artifact: "plain_gzip"`; `[FAILED/1/log, COMPLETED/0/"done"]` | `recompressed_reference_and_retried`, `patch_applied true`, `recovered true` |
| 3 | `container-pull-retry-heal` | `container_pull_failed` | safe patch, no gate; `[FAILED/1/log, COMPLETED/0/"done"]` | `patched_and_retried`, `patch_applied true`, `recovered true` |
| 4 | `download-failed-retry-heal` | `download_failed` | safe patch, no gate; `[FAILED/1/log, COMPLETED/0/"done"]` | `patched_and_retried`, `patch_applied true`, `recovered true` |

### Log text — start from the shipped detector corpus, then check for theft (PRD R5)

Use wording close to the existing corpus cases so the needles are known-good:

- **`missing_reference`** — `Error: No such file or directory: /data/genome.fasta`
  (`detector_corpus.jsonl:7`). Needs the full phrase `no such file or directory` **plus** a
  ref token (`detect.py:310-312`). **Must not** contain `index`, `.fai`, `.bai`, `.tbi`,
  `.csi`, `.dict`, `genomeParameters.txt` — `missing_index` (#10-#15) is checked first.
- **`reference_not_bgzf`** — the three-line faidx log at `detector_corpus.jsonl:24`; the
  trigger needle is `Cannot index files compressed with gzip` (`detect.py:370-372`).
  **Careful:** its third line contains `Could not build fai index …fai`, which carries
  `index` and `.fai`; it survives only because that line has none of #10's absence needles
  (`not found` / `missing` / `no such file`). Do not reword it toward "not found".
- **`container_pull_failed`** — `failed to pull image quay.io/biocontainers/fastqc: manifest
  unknown` (`detector_corpus.jsonl:3`). **Must not** contain `docker.sock` or `cannot connect
  to the docker daemon` (#6 wins) or `permission denied` (#5 wins).
- **`download_failed`** — `Unable to stage foreign file https://example.org/genome.fa.gz:
  connection timed out` (`detector_corpus.jsonl:14`). **Must not** contain `failed to pull`
  (#7 wins).

**Universal:** no `killed`, no `oom`, no `out of memory`, and `exit` must not be `137` — the
`oom` rule sits at position 2 with bare substrings (`detect.py:90`) and will steal any of
these. This is the rule the `no_progress` slice committed to
(`plan_20260725.md:262-263`); it used exit `143` for the same reason.

**Gated classes (1 and 2) must set `auto_approve` or `poll_decision`** or the driver falls
back to the real file poll at `approval_timeout=1800` and the suite hangs 30 minutes
(`heal.py:101-115`, `self_heal.py:959`). PRD R6.

### Integrator step

5. Append the four records to `heal_scenarios.jsonl`, **compact JSON, one physical line each,
   fields in `models.py` declaration order, every optional field written explicitly with its
   default** — matching the nine existing lines byte-for-byte in shape. Multi-line logs use
   `\n` escapes inside the single-line string (see the shipped `approval-approved-heal` line).
6. Each `description` must carry its honesty note where a future reader meets it (the
   `qc_anomaly` precedent, `plan_20260728.md:187`) — for classes 3 and 4, that `apply_patch`
   is a documented no-op and the re-run itself is the fix (`self_heal.py:549`), so
   `patch_applied: true` means *enacted*, not *effective*.

- **Validation:** `uv run pytest tests/test_heal_scenarios.py -q`; `uv run contig heal-guard`
  reports 13 scenarios and **must** still be 100%. A drop means needle theft — diagnose the
  log text, never relax the expectation.
- **Commit:** `feat(heal-guard): cover the four honest repair classes with frozen scenarios`

## Testing strategy

- **Unit (per phase, written first):** the two seam tests (Phase 1); one replay test per
  scenario asserting `matched`, `diagnosed_class`, `actual_outcome`, `patch_applied`
  (Phases 2-3); the back-compat default test; optionally Phase 6's gap test.
- **Integration:** the existing shipped-corpus tests
  (`test_shipped_heal_scenarios_all_reproduce_their_declared_outcomes`,
  `test_shipped_heal_baseline_matches_shipped_scenarios`,
  `test_shipped_heal_report_does_not_regress_against_baseline`,
  `test_evaluate_heal_is_deterministic_over_the_shipped_scenarios`) cover the enlarged corpus
  once literals are updated.
- **CI-identical gate, run before every commit:**
  `uv run pytest && uv run contig eval-guard && uv run contig heal-guard`.
- **Manual verification:** `git diff --stat` must show **no** change to `repair.py`,
  `self_heal.py`, `detect.py`, either detector corpus, or `holdout_baseline.json`.

## Environment & reproducibility

No env var, no external tool, no service. `uv sync` already run. Determinism: `evaluate_heal`
runs each scenario in its own `TemporaryDirectory` (`heal.py:211-212`), so the corpus is
order-independent — pinned by the existing determinism test. Nothing in this aspect touches
the signed record, the bundle, or any exit code, so there is **no signature break**.

## Edge cases & error handling

| Case | Expected handling |
|---|---|
| A scenario classifies as the wrong class | Fix the log text. **Never** relax the expectation (PRD R11). |
| `_recompress_reference` returns `unresolvable` in scenario 2 | The fixture is wrong (missing params, wrong gzip flavor, or already in `built_paths`) — fix the fixture, not the expectation. |
| A gated scenario hangs | Missing `auto_approve`/`poll_decision`; the real poll is waiting out 1800 s. |
| `heal-guard` prints a sha-mismatch warning | Expected between Phase 2/3 and Phase 4; it is non-fatal by design. Must be gone after the refreeze. |
| `outcome_match_rate` lands below 1.0 after the refreeze | Stop. Something is genuinely wrong — do not ship a lowered baseline. |
| `eval-guard` moves at all | A detector corpus was touched, violating R9. Revert it. |
