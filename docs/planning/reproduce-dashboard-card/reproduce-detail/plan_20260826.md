**Files to create:**

   - **Claims table** (mirror qc-panel's `QcRows` table): Claim id, Status (`ReproduceStatusBadge`), Claimed, Observed (`null` → `-`), Tolerance, Delta (`null` → `-`), Message (verbatim, never reworded; muted styling).
   - **Repair history** (mirror repair-timeline conventions): each `RepairStep` — outcome literal, `patch_applied` applied/not-applied marker (only when true), install operation from `patch.operation.install`, `detail`, `diagnosis.root_cause`. Empty list → omit section or render "No repairs" muted line (pick one; mirror what repair-timeline does for empty).
   - **Signature card**: when `hasSignature(id)` — "Signed bundle" with algo + public-key fingerprint (first 8 chars + `…`), a note that presence is shown, verification is not computed this slice. Absent → muted "Unsigned bundle".
   - **Downloads**: three small buttons (record / manifest / signature), each a link to `/api/reproduce/<id>/download?file=<k>` (signature disabled/hidden when absent). Mirror the export button styling from the run detail page.
   - `notFound()` for unknown ids (Next default 404 page).
2. `dashboard/app/api/reproduce/[id]/download/route.ts` — GET, read-only (mirror the export route):
   - `const { id } = await params;` validate id with the same safe-id rule `InvalidRunIdError` uses (find it in `lib/runs.ts` — reuse or mirror; a bad id → 400 with the error message).

## Edge cases

- Unknown id → `notFound()` (404), never a crash.
- `manifest` missing (defensive) → provenance renders from the record; download 404s honestly.
- `signature` missing → section says "Unsigned bundle"; signature download 404s (spec-pinned).
- `observed`/`delta` `null` → rendered as `-`, never "0" or fabricated.
- Unknown claim literal → neutral "Unknown" badge (shared from the list aspect).
- Non-zero `exit_code` → "Did not complete (exit N)" presentation everywhere; claims stay `unverified` with verbatim messages.
- Long values → truncation with `title` full value (provenance-panel convention).
