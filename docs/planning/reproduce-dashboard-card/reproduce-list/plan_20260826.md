1. `dashboard/lib/types.ts` — add TS types (loose by design — tolerate unknown fields; never strict-excess-property on parse):
   - `type ReproduceStatus = "reproduced" | "within_tolerance" | "diverged" | "unverified" | (string & {})` — the `(string & {})` keeps unknown literals type-safe (forward-compat).
   - `interface ReproduceClaim { id: string; status: string; claimed: number; observed: number | null; tolerance: number; delta: number | null; message: string }`
   - `interface ReproduceDiagnosis { failure_class: string; root_cause: string; evidence: string[]; confidence: number }`
   - `interface ReproducePatch { kind: string; operation: Record<string, unknown>; rationale: string; risk: string; expected_signal: string }`
   - `interface ReproduceRepairStep { attempt: number; diagnosis: ReproduceDiagnosis; patch: ReproducePatch | null; outcome: string; detail: string | null; patch_applied: boolean }`
   - `interface ReproduceRecord { reproduce_id: string; repo: string; run_command: string; claims_sha256: string; claim_results: ReproduceClaim[]; exit_code: number; created_at: string; interpreter: string | null; tool: string; repair_history: ReproduceRepairStep[]; source_url: string | null; source_commit: string | null; source_tree_sha256: string | null }`
   - `interface ReproduceManifest { reproduce_id: string; repo: string; run_command: string; claims_sha256: string; created_at: string; source_url: string | null; source_commit: string | null; source_tree_sha256: string | null; requested_rev?: string }`

2. `dashboard/lib/reproduce-derive.ts` — **no `server-only` import** (unit-observable, the `ownership.ts` precedent):

   - `REPRODUCE_STATUS_ORDER: Record<string, number>` — `diverged:0, within_tolerance:1, unverified:2, reproduced:3`; unknown literals resolve to the `unverified` rank (never crash, never a pass).
   - `deriveReproduceOverall(record: Pick<ReproduceRecord,"exit_code"|"claim_results">): { overall: ReproduceOverall; counts: Record<string, number> }` — `did_not_complete` when `exit_code !== 0`; else worst-of over `claim_results` (empty list → `unverified`); counts = per-status tally including unknown literals under their literal key.
   - `claimStatusLabel(status: string): string` — `reproduced`→"Reproduced", `within_tolerance`→"Within tolerance", `diverged`→"Diverged", `unverified`→"Unverified", anything else → "Unknown".

## Edge cases

- Malformed `reproduce_record.json` → skipped in listing (null from `readReproduceRecord`), never a page crash.
- Unknown status literal → neutral "Unknown" badge + counted under its literal key in `counts`; overall derivation treats it as `unverified`.
- Empty `claim_results` → overall `unverified` (honest non-result), counts empty.
- Non-zero `exit_code` → "Did not complete (exit N)", claims still shown as `unverified` on the detail page (detail aspect).
- Very long repo/run command → truncation with `title` full value.
- `runsDir()` unreadable → `listReproduceRuns` returns `[]` (mirror `listRuns`).
