## Phase 1 — the field

**Goal:** `RepairStep` carries `patch_applied`, defaulting `False`, with the semantics
documented on the model itself.

**Prerequisites:** none.

**Files:** `src/contig/models.py`, `tests/test_models.py`.

**Steps:**

1. **RED** — in `tests/test_models.py`, add:
   - `test_repair_step_defaults_patch_applied_false` — construct a `RepairStep` without the
     field, assert `.patch_applied is False`.
   - `test_repair_step_records_patch_applied` — construct with `patch_applied=True`, assert it
     round-trips through `model_dump_json()` → `model_validate_json()`.
   - `test_pre_field_repair_step_json_still_loads` — `RepairStep.model_validate_json()` over a
     JSON string with **no** `patch_applied` key; assert it loads and reports `False`. This is
     the back-compat pin (acceptance #4).
   Run `uv run pytest tests/test_models.py -k patch_applied` → must FAIL.
2. **GREEN** — add to `RepairStep` (`models.py:307-314`):
   ```python
   patch_applied: bool = False
   ```
   with a docstring/comment stating verbatim: *"True iff the patch was **enacted** and the loop
   proceeded to retry. NOT 'the run's configuration was mutated' — `apply_patch` is a
   documented no-op for `code`/`retry` patches (self_heal.py:549), and a fully clamped resource
   bump can leave the target identical. NOT 'the patch worked' — see reproduce's `retry_failed`.
   Defaults False so a pre-field bundle under-claims rather than over-claims."*
3. **REFACTOR** — none expected.

**Validation:** `uv run pytest tests/test_models.py` green.

**Commit:** `feat(models): record whether a repair patch was actually enacted`

   | `test_budget_exhausted_giveup_is_not_recorded_as_applied` | `max_attempts` reached, gated **and** safe variants | `gave_up`, `patch is not None`, `False` |
   | `test_ceiling_giveup_is_not_recorded_as_applied` | resource already at ceiling | `gave_up_at_ceiling`, `False` |
   | `test_failed_index_build_is_not_recorded_as_applied` | `index_builder` returns non-zero | `index_build_failed`, `False` |

## Phase 3 — the signature break, pinned

**Goal:** the break is documented by a test, and its **narrowness** is documented by a second
test. This is the phase that must not be skipped.

**Prerequisites:** Phase 1.

**Files:** `tests/test_signing.py` (or a new `tests/test_repair_patch_applied_signing.py` if
that file's fixtures don't fit — prefer extending the existing one).

**Steps:**

1. **RED** — mirror `tests/test_reproduce_checkout_hash.py:340-381`:
   - A helper building the **pre-change** canonical bytes: `record.model_dump(mode="json")`,
     then strip `patch_applied` from **every** entry of `repair_history` (note: unlike the
     slice-6/8 precedents this is a **nested** strip, not a top-level key deletion), then
     `json.dumps(..., sort_keys=True, separators=(",", ":")).encode("utf-8")`.
   - `test_pre_field_signature_over_a_record_with_repair_history_no_longer_verifies` — sign
     those bytes with `Ed25519PrivateKey`, assert `verify_signature(record, old_sig, pub)` is
     `False`, then assert a freshly written signature **does** verify and differs.
   - `test_pre_field_signature_over_a_record_with_no_repair_history_still_verifies` — the D5
     narrowing: an **empty** `repair_history` serializes byte-identically, so the old signature
     is still valid. **This test is the whole reason we can describe the break as narrow; if it
     fails, the PRD's D5 claim is wrong and the CHANGELOG wording must change.**
   Use the `@requires_signing` marker the existing tests use.
2. **GREEN** — no production change; these tests describe existing behaviour introduced in
   Phase 1. If test 2 fails, **stop and report** rather than adjusting the test.

**Validation:** `uv run pytest tests/test_signing.py` green (or the new file).

**Commit:** `test(signing): pin the patch_applied signature break and its narrow scope`

## Testing strategy

- **Unit:** the 14 self-heal branch tests are the core; each drives a real path through
  `self_heal_run` with scripted seams — the loop and `propose` are never stubbed.
- **Contract:** model default/round-trip/back-compat; signature break + narrowness.
- **Regression:** full `uv run pytest`, then `contig eval-guard` (must stay 0.923) and
  `contig heal-guard` (must stay outcome-match 1.0 — the `recovered` redefinition belongs to
  the sibling aspect, **not** here).
- **No real Nextflow, network, or LLM anywhere.**

---

## Edge cases and error handling

- **Nested strip in the signature test** — the precedents deleted a top-level key; this one
  must recurse into `repair_history`. Getting this wrong makes the test pass vacuously.
- **Empty `repair_history`** — the case that makes the break narrow; explicitly tested.
- **`ReproduceRecord` shares the model**, so its bundles break here even though its recording
  sites are wired in the sibling aspect. Expected; do not "fix" it in this aspect.
- **A resource patch fully absorbed by the clamp** records `True` — correct under D2, already
  argued in the PRD. Do not add a carve-out.
- **An exception from `index_builder`** propagates and records no step at all — not a
  false-positive path, no test needed.
