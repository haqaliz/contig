# Implementation plan — `heal-guard-truth` (2026-07-29)

The only aspect that changes a **committed baseline**. Three phases, three commits, in this
order. Do not reorder: phase 3 is only safe because phases 1–2 have already proved the guarded
number holds.

**Prerequisite:** the self-heal wiring (aspect `patch-applied-field`, Phase 2) must be
committed, because every assertion here drives the **real** loop.

---

## Phase 1 — `expected_patch_applied` on the scenario contract (R7)

**Goal:** the frozen scenarios can assert the new field, and the driver reports a divergence
when the loop disagrees.

**Files:** `src/contig/models.py` (`HealScenario`, ~`:565`), `src/contig/heal.py`
(the `divergence` block, `:162-175`), `tests/test_heal_scenarios.py`.

**Steps:**

1. **RED** — in `tests/test_heal_scenarios.py`:
   - `test_scenario_without_expected_patch_applied_is_unchanged` — a scenario omitting the
     field parses and produces **no** new divergence. This is the back-compat pin: the field is
     **optional**, exactly as the qc-anomaly slice added its own optional `HealScenario` field.
   - `test_patch_applied_mismatch_is_a_divergence` — a scenario declaring
     `expected_patch_applied: true` against a loop path that applies nothing yields a
     `divergence` entry **naming the field**, and `matched is False`.
   - `test_patch_applied_match_is_not_a_divergence` — the positive control. Without it, an
     implementation that never checks the field would pass the other two.
   Run `uv run pytest tests/test_heal_scenarios.py -k patch_applied` → must FAIL.
2. **GREEN** — add `expected_patch_applied: bool | None = None` to `HealScenario`, and in the
   driver compare against `any(step.patch_applied for step in record.repair_history)`,
   **skipping the check entirely when the field is `None`**. Append a divergence string in the
   same style as the three existing ones (`f"patch_applied: expected {...!r}, got {...!r}"`).
3. **REFACTOR** — none expected.

**Validation:** `uv run pytest tests/test_heal_scenarios.py` green. **Do not run
`--update-baseline` yet** — the jsonl is untouched, so `corpus_sha` has not moved.

**Commit:** `feat(heal-guard): let a scenario assert whether a patch was applied`

## Phase 2 — the honest `recovered`, and the one corrected expectation (R8)

**Goal:** `recovered` stops counting a green-by-construction scenario as a recovery.

**Files:** `src/contig/heal.py` (`:153`), `src/contig/data/heal_scenarios.jsonl`,
`tests/test_heal_scenarios.py`.

**Steps:**

1. **RED** — add `test_a_green_run_that_applied_no_patch_is_not_recovered`: drive the
   qc-anomaly-shaped path (every task exits 0, QC reduces to FAIL, one `qc_verdict_flagged`
   step with no patch) and assert `recovered is False`. It currently returns `True` — that
   failure **is** the disclosed artifact, reproduced as a test. Also add
   `test_a_healed_run_is_still_recovered` as the positive control.
2. **GREEN** — `heal.py:153` becomes:
   ```python
   summary = RunSummary.from_events(record.events)
   recovered = summary.succeeded and any(s.patch_applied for s in record.repair_history)
   ```
3. **Correct the frozen expectation** — in `heal_scenarios.jsonl`, set
   `qc-anomaly-verdict-flagged`'s `expected_recovered` to `false`. **Exactly one scenario
   changes.** While here, add `expected_patch_applied` to all nine per the spec's table.
4. **Verify before refreezing** — `uv run contig heal-guard`. Expect:
   - `outcome_match_rate` **1.0** over 9 scenarios — it stays 1.0 *because* step 3 corrected
     the expectation. **If it is below 1.0, STOP and report.** Refreezing at that point would
     hide a real regression behind a baseline update, which is the one thing this aspect must
     never do.
   - `recovery_rate` **0.556** (5/9), down from 0.667.
   - a loud `corpus_sha` mismatch warning — expected, the jsonl changed.

**Commit:** `fix(heal-guard): a green run that applied no patch was never recovered`

**Goal:** the baseline records the corrected numbers, as its own reviewable act.

**Steps:**

2. Confirm the diff shows **only** `timestamp`, `corpus_sha`, `recovery_rate`

3. **Do not touch `heal_history.jsonl`.** It is append-only. Its five recorded

**Commit:** `chore(heal-guard): refreeze the baseline after the recovered redefinition`

The message must state, in its own words: that `recovered` now means *succeeded **and** some
patch was applied*; that `outcome_match_rate` is unmoved at 1.0; that `recovery_rate`
0.667 → 0.556 is a **correction, not a regression**; and that the sixth trend point is
**not comparable** to the prior five. This is the commit a future reader will find when they
notice the discontinuity in the trend — it has to answer them.

## Testing strategy

- Back-compat (optional field), negative (mismatch is a divergence), positive (match is not),
  and the artifact reproduced as a failing test before it is fixed.
- Whole-suite: `uv run pytest`; then `uv run contig heal-guard` and `uv run contig eval-guard`.
- **`eval-guard` must stay 0.923.** The detector corpus contains no `RepairStep`; any movement
  means something leaked out of this aspect.

## Edge cases

- A scenario with `expected_patch_applied: None` must behave **byte-identically** to today.
- `recovered` for a run with an **empty** `repair_history` (nothing ever failed) is now
  `False`. That is correct — nothing was recovered because nothing broke — but confirm no
  existing scenario relies on the old reading.
- `regressed` is computed from `outcome_match_rate` alone (`heal.py:350`), so a moved
  `recovery_rate` cannot fail the build. That is why it is safe to change it — and why it must
  be called out in the commit message rather than left to be noticed.

## Agent execution notes

- **Hard stop:** if `outcome_match_rate` is not 1.0 at the end of phase 2, report and wait.
  Do not refreeze.
- Regenerate `heal_baseline.json` via the CLI; never hand-edit it.
- Do not touch `verification/reproduce.py`, `report.py`, or `dashboard/`.
