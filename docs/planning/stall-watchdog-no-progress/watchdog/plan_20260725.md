REFACTOR), suite green after every phase.

---

## Design decisions settled here (were PRD open questions)

**D1 (O5) — the observer runs off-thread.** `stat()` against a hard-mounted unresponsive NFS
blocks uninterruptibly, and a wedged mount is a headline stall cause. The default observer
therefore performs its reads in a **daemon thread** with a short deadline; if the read does not
return in time, the watchdog keeps its **previous** fingerprint. A read that never returns thus
reads as *no progress observed* — which is the honest interpretation, since a filesystem that
cannot answer `stat()` is not one on which the pipeline is making progress. Daemon threads
never block interpreter exit, so a permanently wedged read cannot hang `contig`.

**D2 (O1/R14) — spawn into a new session, publish the pgid.** The child is spawned with
`start_new_session=True` so the watchdog can `killpg` it without killing Contig itself. Because
that removes the child from the group `cancel_run` reaps, the executor writes the child's pgid
into `status.json` as `child_pgid`, and `cancel_run` reaps it **in addition to** the recorded
`pid`. `lifecycle.py:70-74`'s inaccurate "runs are spawned detached" docstring is corrected in
the same phase.

**D3 (O3) — poll interval is a constant, not a flag.** `_STALL_POLL_INTERVAL_SEC = 30.0`,
module-level, overridable by keyword for tests only — the `resource_ceiling` precedent
(`self_heal.py:61-62`), not the `--approval-timeout` precedent.

**D4 (O4) — runtime-only, no manifest round-trip.** The watchdog settings are **not** persisted
into `LaunchManifest`. A stall is a property of the machine and its I/O, not of the analysis;
baking a timeout into a reproducible manifest would make replay depend on the original host's
speed. Stated in the CHANGELOG so the omission reads as a decision, not an oversight.

**D5 — termination signal ladder.** SIGTERM to the child's group → wait `_STALL_GRACE_SEC`
(5.0) → SIGKILL if still alive. Mirrors `lifecycle._terminate_process_group:69-90`. Python
reports these as negative return codes (`-15` / `-9`), **never 137**, so our own exit code
cannot trip the OOM branch; a trace row written by a dying Nextflow still might, which is
exactly why D6 exists.

**D6 — the `no_progress` branch goes before the OOM check.** Required: OOM wins outright on
`any(e.exit == 137)` regardless of any later branch (`detect.py:41-47`). It must key on a
narrow first-party sentinel, and its test must prove a genuine OOM is unaffected.

**Assumption to verify, not assert (O2):** what a SIGTERMed Nextflow returns and writes to
`trace.txt`. CI cannot observe it; the manual gate covers it.

## Phase 1 — The pure stall decision (`src/contig/stall.py`)

**Goal:** the CI-testable core, in the `resource_sizing.py` mould. No subprocess, no sleeping,
no filesystem.

**Files:** create `src/contig/stall.py`, `tests/test_stall.py`.

**Steps**

1. `Heartbeat` — a frozen dataclass/`BaseModel` of comparable observations:
   `trace_mtime: float | None`, `trace_size: int | None`, `nflog_mtime: float | None`,
   `nflog_size: int | None`, `runlog_size: int | None`. Absent surfaces are `None`.
2. `changed(previous: Heartbeat | None, current: Heartbeat) -> bool` — True if **any** field
   differs. A first observation (`previous is None`) counts as changed (a run that just started
   is alive). **A surface going from a value to `None` counts as changed** (something happened);
   `None` → `None` does not.
3. `StallDecision` — `{stalled: bool, idle_sec: float, silent_surfaces: tuple[str, ...]}`.
4. `evaluate_stall(previous, current, last_change_at, now, timeout_sec) -> StallDecision` —
   pure. If `changed(...)`, `idle_sec = 0.0`, not stalled. Else `idle_sec = now - last_change_at`
   and `stalled = idle_sec >= timeout_sec`. `timeout_sec <= 0` → never stalled (a disabled
   watchdog can never fire even if wired by mistake).
5. `stall_message(idle_sec, timeout_sec, silent_surfaces) -> str` — the single source of the
   sentinel text. **Must contain the phrase-level needles the detector keys on and must NOT
   contain** `killed`, `oom`, `out of memory`, or `time limit`. Proposed:

   > `contig watchdog: no forward progress for 3600s (limit 3600s); no new output or trace update on trace.txt, .nextflow.log, run.log; terminating the stalled run.`

   Add a module-level test asserting the forbidden substrings are absent — so a future reword
   cannot silently reintroduce the OOM collision.

**Validation:** `uv run pytest tests/test_stall.py`. Covers A1, A2.
**Commit:** `feat(stall): pure stall decision over heartbeat fingerprints`

## Phase 2 — The heartbeat observer (non-blocking)

**Goal:** turn a run dir into a `Heartbeat` without ever hanging the watchdog (D1).

**Files:** modify `src/contig/stall.py`; extend `tests/test_stall.py`.

**Steps**

1. `HeartbeatObserver = Callable[[Path, Path], Heartbeat]` — `(run_dir, artifact_path)`. This is
   the injected seam; tests supply fakes, mirroring `ApprovalPoll` (`self_heal.py:297-300`).
2. `read_heartbeat(run_dir, artifact_path) -> Heartbeat` — `stat()`s `artifact_path`,
   `run_dir/".nextflow.log"`, `run_dir/"run.log"`. Every `OSError` (including
   `FileNotFoundError`) → that field is `None`. **Never call `parse_trace_file` here** — it has
   no existence guard and raises `FileNotFoundError` (dig finding); we only need `stat`.
3. `observe_with_deadline(observer, run_dir, artifact_path, previous, deadline_sec) -> Heartbeat`
   — runs `observer` in a **daemon** thread, waits `deadline_sec`; on timeout returns
   `previous` unchanged (or an all-`None` `Heartbeat` when `previous is None`). Document that
   the thread may leak against a wedged mount, and why that is acceptable (daemon).

**Validation:** `uv run pytest tests/test_stall.py` — including a fake observer that blocks on
an `Event` and must not exceed the deadline. Covers A3.
**Commit:** `feat(stall): non-blocking heartbeat observer over trace/nextflow.log/run.log`

## Phase 3 — Detector and repair (independent of 1–2; can run in parallel)

**Goal:** make `no_progress` classifiable and repairable.

**Files:** modify `src/contig/detect.py`, `src/contig/repair.py`; extend `tests/test_detect.py`,
`tests/test_repair.py`.

**Steps**

1. In `diagnose_failure`, **before** the OOM block (`detect.py:40`), add:
   ```python
   stall_lines = _matching_lines(log_text, _NO_PROGRESS_NEEDLES)
   if stall_lines:
       return Diagnosis(failure_class="no_progress", ...)
   ```
   with `_NO_PROGRESS_NEEDLES = ("no forward progress", "no new output or trace update",
   "terminated it as stalled", "terminating the stalled run")`. Phrase-level, so both our
   emitted message and `holdout-no-progress-1` match without either being fitted to the other.
   Add a comment stating **why** it precedes OOM (a first-party watchdog statement outranks an
   incidental exit code) — the file's existing "OOM wins outright" comment must be amended, not
   left contradicting the code.
2. Tests, all required:
   - our `stall_message(...)` output → `no_progress`;
   - the verbatim `holdout-no-progress-1` `log_text` → `no_progress`;
   - **an OOM with `exit=137` and no stall text → still `oom`** (A5);
   - **an OOM by text ("out of memory") → still `oom`** (A5);
   - a stall message *plus* an incidental exit-137 event → `no_progress` (the case D6 exists
     for);
   - `diagnose_failure_strict` leaves `no_progress` undemoted.
3. `propose_patches` (`repair.py`): add a `no_progress` branch returning one
   `Patch(kind="retry", operation={"retry": True}, risk="safe",
   rationale="No forward progress; terminate and retry from the last completed task.",
   expected_signal="tasks progressing again")`. Retry is cheap because `self_heal.py:981`
   already passes `-resume`.

**Validation:** `uv run pytest tests/test_detect.py tests/test_repair.py`, then bare
`uv run contig eval-guard` — expect an **improved** report (12/13), not a failure. Covers A4,
A5, A6.
**Commit:** `feat(detect): classify no_progress ahead of the OOM check, with a safe retry patch`

## Phase 4 — The watchdog executor (needs 1, 2)

**Goal:** an `Executor` that supervises the child and terminates a stalled run.

**Files:** modify `src/contig/runner.py`; create `tests/test_stall_executor.py`.

**Steps**

1. `make_watchdog_executor(*, stall_timeout_sec, observer=read_heartbeat, clock=time.monotonic,
   sleeper=time.sleep, poll_interval=_STALL_POLL_INTERVAL_SEC, grace_sec=_STALL_GRACE_SEC)
   -> Executor` — returns a closure of exactly `(cmd, trace_path) -> int`. **The `Executor`
   alias does not change** (`runner.py:567`); all 38 test fakes keep working.
2. Inside: open `run.log` for write (same path/mode as `default_executor`), `Popen` with
   `cwd=trace_path.parent`, `stdout=log`, `stderr=STDOUT`, **`start_new_session=True`** (D2).
   Record `os.getpgid(proc.pid)` into `status.json` as `child_pgid` (merge, don't clobber).
3. Poll loop: while `proc.poll() is None`, `sleeper(poll_interval)`, observe via
   `observe_with_deadline`, `evaluate_stall(...)`. On `stalled`: append `stall_message(...)` to
   `run.log` (**flush before terminating** — the message is the detector's only input), then
   `killpg(SIGTERM)` → wait `grace_sec` → `killpg(SIGKILL)` if alive. Terminate **at most once**
   per invocation.
4. Return `proc.returncode` unchanged (`-15`/`-9` for a terminated child — non-zero, so
   `run_pipeline` raises `PipelineExecutionError` and the existing diagnosis path runs with no
   new plumbing).
5. `stall_timeout_sec <= 0` → skip the watchdog entirely and delegate to `default_executor`.

**Tests** (a real child process is safe and fast here — this is genuine coverage, not
reasoning): a `[sys.executable, "-c", "import time; time.sleep(60)"]` child with an injected
clock/observer that reports silence must be terminated, return non-zero, and leave the stall
message in `run.log`; a short-lived child that exits normally must return its own code
untouched and never be terminated; a child whose observer reports change must not be
terminated. **No Nextflow.**

**Validation:** `uv run pytest tests/test_stall_executor.py`. Covers A7.
**Commit:** `feat(runner): watchdog executor that terminates a stalled run`

## Manual gate (pre-merge, not CI)

Not optional — it is the only evidence for the parts CI cannot reach:

1. Launch a real `nf-core/rnaseq` test-profile run with `--detect-stalls --stall-timeout 60`.
   Confirm a healthy run is **not** terminated (the composite heartbeat should keep it alive
   even during a long task) — the single most important false-positive check.
2. `kill -STOP` the Nextflow child mid-run to simulate a hang; confirm the watchdog fires,
   `run.log` carries the message, the diagnosis is `no_progress`, and the retry `-resume`s.
3. Record the **actual** exit code and what `trace.txt` contains for the terminated run (O2).
   **If a trace row shows exit 137, confirm D6's ordering saves the classification.**
4. Run `contig cancel` against a watchdog-enabled run; confirm no orphaned Nextflow
   (`pgrep -f nextflow`).

## Edge cases to cover

- No `trace.txt` yet (killed before Nextflow wrote one): `run_pipeline` builds no record;
  `diagnose_failure([], log_text)` still classifies from the message alone.
- Child exits during the grace window → no SIGKILL, no error.
- `status.json` absent/unwritable when publishing `child_pgid` → warn, never fail the run.
- Clock going backwards (`time.monotonic` cannot, but an injected clock can) → clamp
  `idle_sec` at 0.
- A stalled run at `attempt == max_attempts` → `gave_up`, not an extra window.
